# Reductions and search modes beyond TLC

This page is the developer contract behind tlx's two checking modes and the one reduction they
differ by: what the default mode may do, which guarantee each reduction keeps, how the proof and its
runtime obligations work, and what the test drivers do with a reduced run.
[compat.md](compat.md) section 0 owns the tier contract a user relies on, [usage.md](usage.md) section 6 owns what a
user sees, and [configuration.md](configuration.md) owns the options and their defaults.

**Automatic symmetry is the only reduction implemented.** The other techniques this page's contract
was designed for (sleep sets, partial-order reduction, bounded and swarm search, bitstate storage,
incremental re-checking, 128-bit fingerprints) do not exist in the code; §5 lists them with the
evidence. Their proposals and the measurements that ranked them are archived — [README.md](README.md)
names the pinned revision that holds them.

## 1. Modes and the guarantee contract

### 1.1 Guarantee symbols

A reduction is described by which of these it keeps, and the same vocabulary is what `-stats json`
reports in `preserved` (§3) and what [scripts/contract.py](../scripts/contract.py) consumes to decide
which fields may be compared with a TLC oracle:

| Symbol | Meaning |
|---|---|
| **V-safe** | invariant, action-property, deadlock, ASSUME and POSTCONDITION verdicts and violated names equal the `-tlc` run |
| **V-live** | temporal-property verdicts equal, and every reported property is violated by the reported lasso |
| **CEX** | every counterexample is a genuine behavior of the spec: each step a successor under `Next`, the initial state in `Init`, the final state or lasso really violating the property |
| **N-dist**, **N-gen** | the distinct and the generated counts equal `-tlc`'s |
| **D** | the search depth equals `-tlc`'s |
| **L** | a safety counterexample has the BFS-shortest length |
| **Complete** | "no violation found" means none exists, up to the usual fingerprint caveat |

### 1.2 What the default mode may use

The default mode (no `-tlc`) is the fastest **sound** checking; `-tlc` is the parity contract of
[compat.md](compat.md) section 0. A technique may run without a flag only if it keeps V-safe, V-live (when
liveness is checked), CEX and Complete, and only if it applies without trusting an unchecked claim: a
technique that rests on an unproven assumption or gives up exhaustiveness needs its own flag, which
does not exist yet (§5). A user's own `SYMMETRY` declaration is not such a claim — TLC trusts it too.

Two further requirements come with "no surprise". The default must not be slower than `-tlc` beyond
the cost of its own analysis, and it must not change side effects a spec can observe: a spec whose
behavior depends on run-time statistics or registers (`TLCGet` of statistics, `TLCSet`/`TLCGet`
registers, `RandomElement` at state level, IO) is not reduced, with a one-line note.

### 1.3 Classes

- **Class A, default-eligible.** Sound, exhaustive, and proven to apply. Automatic symmetry is the
  only implemented member; `-tlc` turns it off, and each one has an explicit off switch
  (`-noautosymmetry`) for diagnosis.
- **Class B, explicit.** Gives up exhaustiveness, or rests on an unproven assumption. It needs a
  flag that names what is given up, and a "no violation found" result is labelled incomplete. No
  class B technique is implemented, so no such flag exists today (§5).
- **Class C, diagnostic.** Changes no result — a suggestion or an estimate. The symmetry analysis
  reports its suggestion in every mode, `-tlc` included, because it changes nothing.

## 2. Automatic symmetry

A CONSTANT whose cfg value is a set of model values names interchangeable identities in most specs,
but users forget to declare it. tlx looks for those sets, proves which of them the spec is invariant
under, and applies the proven group to the safety search in the default mode. The reduction itself is
TLC's: the search explores one representative per orbit, and the counts of a reduced run are the
counts of the quotient.

### 2.1 Candidates

A candidate is a cfg-bound CONSTANT whose value is a set of at least two model values of one
model-value type, and that is not already covered by a declared `SYMMETRY`. If another constant's
value mentions some elements individually (`Leader = r1`, `Quorums = {{a1, a2}, ...}`), only the
permutations that fix those values are allowed, so the candidate group is the product of
`Permutations` over the classes of elements that every other constant value treats alike. The
analysis takes the subgroup generated by the transpositions it admits; transpositions do not generate
every automorphism of a graph, so the rest is reported as not detected.

### 2.2 The static proof

The proof (`tlx-eval/src/model/autosym/`) is an abstract interpretation of the specification over
*shapes*, not a bounded test. It records, for every expression position, which set elements a value
can be derived from (a mask per shape), which effects the specification performs, and which constant
values (atoms) it reads. A set is proven when no *breaker* applies to its elements and every atom the
specification reads is fixed by the permutation.

Breakers reject the set and report the location: `CHOOSE` (unless it is provably unique or a
commutative fold), `SetToSeq`, `SetMax`/`SetMin`, `ToString` and the JSON/FP writers, `CausalOrder`,
`ChiSquare`, `TLCModelValue`, the `RandomElement` family, IO and serialization, and a constant whose
value is unknown or unrepresentable. Effects — `Print`/`PrintT`, `TLCGet`/`TLCSet`, `JavaTime`,
`Trace`, IO and JSON — do not break the proof by themselves but rule out any count-changing reduction
for that specification. The proof covers safety checking only: initial states, successors,
invariants, constraints, action constraints, action properties and deadlock.

The analysis is bounded, and a bound is not a proof of the contrary: it stops at shape depth 6, 256
frames, 4,000,000 steps and 12 passes, analyzes at most 64 candidates, and marks itself *incomplete*
when a bound is reached, in which case nothing is applied.

### 2.3 Runtime guards

A `CHOOSE` rejects a set whose projections the analysis can, however, recognize: for a choice over
exactly the elements of the candidate set, the chosen element is a projection of the state, and the
search can carry a guard. The group is then admitted with a **runtime guard** instead of a proof, and
the guard is checked as the run proceeds. If a guard fails — the projection it assumed does not hold
for some state — the run **discards the reduced search and restarts from `Init` without automatic
symmetry**, clears the reduction label, and does not publish the interrupted search's verdict,
counters, dump or checkpoint as a result. The restarted run is the unreduced run, so the verdict is
the one the `-tlc` run would give.

### 2.4 The bounded cross-check

Before a group is applied, a bounded cross-check of the group runs as a cross-check of the proof
(`symcheck::check_perms`) on the **unreduced** system: for each of at most 1000 states, up to 10
levels deep, at most 100 permutations and 10000 edges, it compares `Init` membership, invariants,
VIEW commutation, state constraints, successor sets in both directions, action constraints and
action properties. The check has a 20 ms wall-clock budget and is reported as its own phase in
`-stats`. A witness from a group that was *proven* is an internal error and exits 101, because the
proof and the bounded check disagree; with a runtime-guarded group the witness instead means
"not applied: conditional symmetry failed its bounded check", and the run continues unreduced.

A group larger than 720 elements is not applied: the search tries every element of the group on each
state it finds, so the cost of the canonical form grows with the group. Skipped groups are named
under `-stats`.

### 2.5 When it is applied

Application happens once, after the model is built and before the search, and only in the default
mode. Under `-tlc` the analysis runs for its suggestion and nothing is applied, so `-tlc` output is
unchanged except for that line. A group is not applied when the specification has a declared
`SYMMETRY`, a `VIEW`, temporal properties, a state-dependent effect, or an incomplete analysis — each
reason is reported under `-stats`. `-noautosymmetry` turns the whole reduction off.

`-checksymmetry` is the separate declared-symmetry diagnostic: it looks for a genuine violation of a
declared `SYMMETRY` within its bounds on an unreduced breadth-first search in the interpreter, and
reports `No symmetry violation found within bounds (...). This is not a proof of symmetry.` A
successful bounded run is evidence, never a proof, and a run that hit a bound says
`Symmetry check incomplete` and exits 2 instead of reporting either. `-checksymmetry -suggest` runs
the same check for the candidates the analysis could not prove.

### 2.6 Guarantees

A proven group preserves **V-safe, CEX, D and L**: invariants, constraints and action properties are
symmetric by the analysis, a state is deadlocked iff its images are, and all members of an orbit lie
on the same BFS level, so depth and the length of the shortest counterexample are exact. It does not
preserve **N-dist** or **N-gen** — those are the counts of the quotient, as with a declared
`SYMMETRY` — and a runtime-guarded group is only as sound as its guard. Liveness is not reduced (a
specification with temporal properties is not reduced at all), so V-live holds trivially.

## 3. The labelling contract

Every run not under `-tlc` states which optimizations were active; the exact text, its message code
and the `-stats json` shape are [usage.md](usage.md) sections 6.2–6.3. What matters here is the contract they
implement:

- the `optimizations` array of `-stats json` carries `name`, `scope`, `proof` (`static`, `runtime
  guard`, or `none` for a forced group), `preserved` (the symbols of §1.1) and `detail` (the group);
- the reduction names itself in the final statistics line (`(symmetry-reduced)`), and the start line
  says the counts refer to the reduced search;
- a `-dump` file of a reduced search says so in its header; a `-dumpTrace` counterexample is
  unchanged, because a counterexample is a genuine behavior in every mode;
- the generated performance report preserves the label per row: `tlx optimizations` carries the
  optimization the recorded samples name, `none` means every recorded sample states an empty list,
  and `unknown` means the record does not state it. The column speaks for the tlx side only - a TLC
  baseline may declare its own `SYMMETRY` - so it does not by itself claim what the other side
  explored;
- the label is cleared when a guarded reduction restarts, so a restarted run never claims a reduction
  it no longer has.

A reduction does not change any exit code: V-safe means the verdict, and therefore the exit code, is
the parity contract's. [usage.md](usage.md) section 10.3 owns the exit-code table.

## 4. The oracle guard in the test drivers

The numbers of a reduced run must never be compared with a TLC oracle as if they were TLC's, and a
forgotten flag must fail loudly instead of producing a plausible wrong result. `scripts/tlc.py`
records the `Optimizations:` start line, and `contract.compare` refuses a run that used optimizations
unless the caller asked for the default mode; then it compares only the verdict and the fields of
`preserved`. `spectest.py`, `difftest.py` and `tlxsuite.py` pass `-tlc` by default and opt in with
`--default-mode`; the benchmark report refuses to compare counts of a reduced run the same way.
[testing.md](testing.md) owns the tiers these drivers run in.

## 5. Not implemented

Searching the CLI option table and the tree for the spellings of the rest of the design finds none of
them: `-nosleep`, `-nopor`, `-maxlevel`, `-swarm`, `-bitstate`, `-recheck` and `-symmetry trust` are
not options (an unknown option is rejected with exit 2), and there is no sleep set, partial-order
reduction, bounded search, swarm mode, bitstate storage or incremental re-check in any crate. The
incomplete-search exit code 4 that a class B technique would use is likewise a proposal: it is unused
by TLC and by tlx, and no code produces it. Sleep sets, partial-order reduction and bounded search
were measured and ranked; the ranking and the reasons are in the archived proposal named in
[README.md](README.md), not in current documentation.

## 6. Tests

- `crates/tlx-eval/tests/autosym.rs` and its `autosym_families` sibling — one specification per
  proven operation class and per breaker class, asserting the exact rejection and its location.
- `crates/tlx-cli/tests/autosym.rs` — the suggestion under `-tlc`, application in the default mode,
  `-noautosymmetry`, a violation keeping TLC's trace length, temporal properties and `PrintT` keeping
  the full search, the checkpoint recording the group, `-checksymmetry -suggest`, the paranoid check
  catching a wrong proof, `TLX_AUTOSYM_FORCE` and the guarded `CHOOSE` case, a late guard failure
  restarting the unreduced search, and the exact `optimizations` JSON with the dump header and the
  tool message code.
- `crates/tlx-cli/tests/symcheck.rs` — the declared-symmetry diagnostic: each predicate checked
  independently, an inconclusive cutoff never reported as a violation, `VIEW` commutation, and the
  diagnostic forcing the interpreter and one worker under `-compile`.
- `scripts/tests/test_contract.py` — the `optimizations` parse, the empty list for `none applicable`, an
  unknown optimization preserving nothing, and the refusal to compare the counts of a reduced run.
- `scripts/autosym_mutants.py` (with `scripts/tests/test_autosym_mutants.py`) — mutation tests: invariant
  and deadlock mutants derived from the unreduced state graph must be found in the default mode with
  the `-tlc` depth and trace length, and a default run that was not reduced is a failure, not a pass.
- `scripts/autosym_guards.py` — guarded runs against small TLC declared-symmetry oracles across the
  interpreter, closure, C and JIT executors, including the restart case.
