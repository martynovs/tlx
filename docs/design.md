## 1. Goals and approach

### 1.1 Goals

1. **Performance.** On specs TLC can handle, explicit-state BFS throughput well above TLC (single-thread target at least 5x), scaling with cores, with much less memory per state.
2. **TLC-identical results** (the `-tlc` contract). Same verdicts and violated names (tier 1), and same generated/distinct counts, search depth and BFS counterexample length (tier 2). TLC is the semantic oracle; the order of authority is **TLC > tlx interpreter > tlx compiled tier**. [compat.md](compat.md) section 0 defines the contract and the incidental choices that only have to be valid (error class and exit code, print order, which equally short counterexample).
3. **A drop-in workflow.** Reads `.tla` + `.cfg`; TLC-style options, output text, `-tool` message codes and exit codes (§8.1).
4. **Graceful degradation.** What the compiled tier cannot handle statically falls back to the interpreter at (state, action) or expression granularity instead of rejecting the spec (§6.4, [mixed-mode.md](mixed-mode.md)).

### 1.2 Non-goals

- Proofs (TLAPS) and symbolic checking (Apalache style).
- Distributed (multi-machine) checking; tlx is single machine, multi-core.
- A Java or SANY dependency at run time. The syntax layer is tree-sitter-tlaplus, the semantic layer is written in Rust. SANY and TLC are test oracles only.
- NUMA-aware fingerprint-set sharding (§7.7).

### 1.3 Why it can be faster than TLC

| Cost in TLC | TLC | tlx |
|---|---|---|
| Expression evaluation | recursive interpretation of the semantic tree, linked-list `Context` lookups | compiled tier: a specialised C (or JIT) function per action instance (§6.7); the interpreter also caches heavily (§5.3) |
| Value representation | `Value` objects, heavy allocation and GC | compiled tier: fixed-length word-array states (§6.2); sets become bitsets or sorted arrays, functions arrays or maps, records concatenated fields |
| Set normalisation | sort to normalise before compare/fingerprint | canonical encoding (semantic equality iff encoding equality); bitsets are ordered by construction |
| Fingerprinting | serialises a `Value` recursively into FP64 | compiled tier: one fast hash over the fixed word array (`tlx_fp_words`, 8 independent lanes) |
| Successor generation | generic enumerator, interprets each conjunct | one dedicated function per action instance (continuation-passing, statically known assigned variables) |
| Constants | re-evaluated at run time (partly cached) | evaluated and folded at compile time (CONSTANTS come from the `.cfg`) |
| Dedup table | `MultiFPSet`, lock striping | lock-free open-addressing `AtomicU64` table, one CAS per insert (§7.2) |

The central idea is **whole-spec specialisation**. Once the `.cfg` fixes every CONSTANT, tlx can fold constants, inline operators, expand `\E i \in Procs` into action instances, guess a concrete *shape* for every variable, and emit a checker that serves only this model. Shapes come from **speculation + guards + recompilation** (§6.5), not from pure static inference: TLA+ is untyped, static abstract interpretation is imprecise for CHOOSE, recursion, higher-order operators and set comprehensions, while the interpreter already agrees with TLC and is a reliable observer.

## 2. Architecture

```
 .tla ──► tree-sitter-tlaplus ──► CST ──► surface AST          (tlx-front)
                                            │ module loading, name resolution, INSTANCE,
                                            │ SANY-style scoping, precedence, level checks  (tlx-sema)
 .cfg ──► cfg parser (tlx-front::cfg)       ▼
   │                                    HIR (tlx_sema::hir::Program)
   └──────► constant bindings / intern order / model construction ◄┘   (tlx-eval::interp)
                                            │
               ┌────────────────────────────┴──────────────────────────────────┐
               ▼                                                               ▼
     interpreter: InterpModel (-interp)                              EncModel (default)
     tlx-eval: reference implementation of TLC semantics             pre-run guesses shapes → fixed-size layout (tlx-layout)
                                                                    → typed IR (tlx-compile::lower)
                                                                    → closure executor / JIT / generated C (cgen)
                                                                    → cc + dlopen in the background (tlx-native)
                                                                    → per-(state, action) fallback to the interpreter
               └────────────────────────────┬──────────────────────────────────┘
                                            ▼
              tlx-runtime (generic over the Model trait): BFS, level-synchronous workers,
              fingerprint set, trace reconstruction, checkpoint/resume, simulation,
              -dump, live statistics, liveness orchestration (behavior graph → tlx-live)
                                            ▼
              tlx-cli: TLC-style report; liveness counterexample rendering; POSTCONDITION
```

The key point: **the runtime is generic over the `Model` trait** (§7.1). Both models use the same parallel runtime, the same reporting and the same liveness path. The compiled tier is the default (`-interp` selects the interpreter; with no possible native code, no JIT and no C compiler, the default is the interpreter); the interpreter is the differential baseline for the compiled tier, and its fallback.

### 2.3 Value representations and their contracts

A TLA+ value has five representations in tlx. They are not interchangeable: each has its own
identity, lifetime and failure mode, and all five are bound by the same three contracts:

1. **Denotation.** Two equal finite values have one semantic normal form and one semantic
   fingerprint; aliases (a tuple, a record and a function with the same graph) compare and hash as
   equal. A hash collision is never evidence of equality.
2. **Evaluation.** TLC's comparison errors, function application, lazy forcing, iteration order,
   duplicate enumeration and side effects are preserved. Equal denotations do not license
   substituting one representation for another in every evaluation context: an interval-domain and
   an enumerated-domain function reject an ill-typed key differently.
3. **Physical storage.** Offsets, handles, capacity, tree shape, compression and cache residency are
   implementation choices. Changing one may change neither of the other two contracts, and may not
   require rediscovering states already visited.

| Representation | Where it lives | Identity and lifetime | Failure mode | Consumed by |
|---|---|---|---|---|
| Boxed `Value` | `tlx-value` | the interpreter's canonical value; subvalues shared by `Arc`; string and model-value order is the process's intern order | a TLC evaluation error | `tlx-eval`; every compiled fallback; traces, POSTCONDITION and ALIAS, evaluated on decoded values |
| Encoded state words | `tlx-layout` (`shape.rs`, `layout.rs`, `layout_tree.rs`) | a `[u64; W]` per state, canonical within one shape (`encode(a) == encode(b)` iff `a == b`, unused words 0); fingerprint `tlx_fp_words` | a value outside the shape is a **layout miss**: the search stops, widens and resumes — never a wrong answer | all three compiled executors; the queue and checkpoint codecs |
| `Dyn` handle | `tlx-layout::dynval` | one word: a kind tag plus the payload for a scalar, otherwise an entry of the run's global interner; canonical within one run (interner order), restored exactly by a checkpoint | none at run time (it is the representation of an open universe); it costs an indirection and a sharded lock | the compiled tier's escape path, and the enclosing union or Map it turns into `Dyn` |
| Host value handle | `tlx-native::mixed` (ABI v3) | a `u64` handle to a `Value` owned by the calling thread's arena, valid for one native call (`mark`/`release`) | a stale handle is a host panic; generated code never dereferences one | C and JIT code with boxed subtrees, through `host->eval` and `host->elems` |
| `Ref` value-store handle | `tlx-layout::store` (ABI v5, `TLX_VALUE_STORE`, experimental, default off) | a handle to an immutable node of the run's store; interning is by exact representation (kind, function witness, child handles), so equal values with different witnesses get different handles, while a handle-independent semantic digest serves as the state fingerprint | the store's byte budget is exhausted, which is a run error | `ir::ExprKind::RefOp` and the `ref_op`/`ref_elems` callbacks, in all three compiled executors |

Only the first four are current behavior; the fifth is the experimental slice of
[value-store.md](value-store.md). Every crossing between two
representations is a checked boundary: `tlx_layout::scalar` owns the handle tag schema that the `Dyn`
interner, the value store and the C and JIT backends all derive from (ARCH-07), `shape::fit_repr`
owns the conversions between a tuple, a record and a constant-domain function, and `verify.rs`
checks the widths of the raw encoding fragments a concatenation uses.

### 2.4 Executors and the coverage they are meant to have

The compiled tier has three executors over one typed IR, with the interpreter as the semantic
reference and the fallback (the tier order and the switches are §6.6). Which of them is *meant* to
run what is a design decision, not an accident of what each happened to compile:

| Executor | Representation it reads | Coverage it is meant to have, and its deliberate gap |
|---|---|---|
| Interpreter (`tlx-eval`, `-interp`) | boxed `Value` | Every construct: the pre-run and every fallback of the compiled tier, functions that are not lowered or not pure, `-generate` actions, traces, POSTCONDITION and ALIAS. It is the semantic reference, so it has no expression-coverage gap; its gap is speed |
| Closure IR executor (`tlx-compile/src/exec/fast/`) | encoded words, and `Value` at the `Interp` nodes it contains | Functions with no `Interp` node, and functions the native backends cannot express; the host side of mixed-mode regions; the executor while the native library is not ready. Deliberate gap: it does not step into and out of an `Interp` node per action (`exec_ok`) — crossing node by node is slower than interpreting the action, so that action goes to the interpreter whole |
| Cranelift JIT (`tlx-compile/src/jit/`) | encoded words, the same ABI as C | The `NativeSet` the C generator chose, at the same region call sites (`native_plan.rs`, `RegionCursor` proves each region is called exactly once). Deliberate gap: it does not decide its own native set; a difference from the plan disables the JIT and C is used |
| C (`tlx-compile/src/cgen/` → `cc` → `dlopen`) | encoded words, the same ABI | The reference backend: every function the plan marks native, plus boxed subtrees as host regions in mixed mode. Deliberate gap: a function body it cannot generate returns `TLX_UNSUPPORTED`, which sends that call to the interpreter |

All four tiers are held to each other, not just to themselves: the three compiled executors are
compared by the testkit's differential tests, the whole compiled tier against the interpreter state
by state under `TLX_PARANOID` (§6.5.5), and the tier as a whole against TLC by the compatibility
tiers (§8.2). Coverage is measured rather than assumed: `scripts/coverage.py` and `TLX_COVERAGE=1`
report per model how much of an action instance, invariant or action property is lowered, native and
fully typed, and the census with its histograms is [native-coverage.md](native-coverage.md);
§6.8 lists why the remaining boxed nodes stay boxed.

### 2.5 Shared concurrency infrastructure

`tlx_base::par` provides the ordered `Pool` (`map_chunks` concatenates successful results in input order; if several chunks fail the error of the first worker in join order is propagated, not necessarily the earliest input position), panic abort and join, and `OneShot`. `for_each_part` runs part 0 on the calling thread. `tlx_base::stack` spawns named threads with a chosen stack size: evaluation and pre-run use 512 MiB (`EVAL_STACK_SIZE`), resume transcoding the default stack; `Stack::Eval` only configures new threads, it does not enlarge the caller's stack. The search's level barriers, safepoints and long-lived workers are deliberately not part of the shared pool: each of them exists once, in `tlx-runtime`, and is tuned where it is used. `tlx-base` owns the pool and the big-stack threads, and every consumer names them at that defining path (`tlx_base::{par, stack}`): `tlx-runtime` re-exports neither, so the leaf crate is their only owner (ARCH-02, ARCH-03).

### 2.6 Execution modes (`tlx check`)

[configuration.md](configuration.md) is the only list of options and variables (`tlx check -h` prints the same list; argument parsing is in `tlx-cli/src/args.rs`).

- **Backend.** The default is the encoded-state compiled tier (`-compile`; `tlx_compile::enc::check`, at most 16 recompilations); with no possible native code, no JIT and no C compiler it falls back to the interpreter (logged). `-interp` selects the interpreter (`InterpModel`), the reference implementation of TLC semantics. Executor tiering is §6.6; the degraded enumeration semantics are cross-checked state by state by `TLX_PARANOID` (§6.5.5). The CLI completes reports, liveness and simulation for both models through the `Tier` trait.
- **Compatibility.** Independent of the backend, `-tlc` asks for TLC-identical results (tiers 1 and 2, [compat.md](compat.md) section 0); the default mode is sound and may use optimizations TLC lacks (counts, depth and counterexample may then differ).
- **Automatic symmetry (default mode).** After the model is built and before the search, `tlx_cli::autosym::run` asks `tlx_eval::model::autosym` which sets of model values can be proven symmetric, cross-checks the proof on a bounded sample and, in the default mode only, applies the proven group to the search, naming the optimization in the run's start line and statistics. Under `-tlc` it prints the suggestion only; `-noautosymmetry` turns it off and `-checksymmetry` runs the declared-symmetry check (`tlx_cli::symcheck`, `tlx_eval::model::symcheck`) instead. The user-facing contract is [usage.md](usage.md) sections 6.2–6.3; the proof, its runtime guards and its bounds are [reductions.md](reductions.md) section 2.
- **`-simulate` / `-generate`**: random simulation (§7.5), combinable with `-compile`.
- **`-dump`**: write all reachable states. Under `-compile` the search may restart, so a dedicated second search writes the file.

### 2.7 Environment switches

All `TLX_*` variables are declared once in the `KNOBS` table (`tlx-base/src/knobs.rs`: name, type, default, description, audience, reading crate) and parsed by the typed readers of `knobs::Env` (one value syntax and one set of error texts). The `-h` environment section is generated from the table. The compiled tier's `Settings` (`tlx-compile/src/settings.rs`) and the CLI's `Env` (`tlx-cli/src/settings.rs`) take values only through the table; the front end validates all values at startup. Meanings and defaults are written only in [configuration.md](configuration.md); `crates/tlx-cli/tests/config.rs` checks that it agrees with the table.

## 3. Front end (`tlx-front`, `tlx-sema`)

### 3.1 Syntax: tree-sitter-tlaplus

- `.tla` is parsed with `tree-sitter-tlaplus`; the grammar handles indentation-sensitive `/\` `\/` lists, precedence and Unicode symbols. `ERROR`/`MISSING` nodes become syntax errors with line and column (`parse/syntax.rs`); all errors in a file are reported at once.
- The CST is lowered to a **surface AST** (`ast.rs`): `Module { name, extends, units }` where a unit is `Constants / Variables / OpDef / FnDef / Instance / Recursive / Assume / Theorem (named, statement is an expression) / Module (nested)`. All operator applications become `OpAppl` with a canonical name (`parse/ops.rs`). Proofs, `USE`/`HIDE` and unnamed theorems are dropped; PlusCal is consumed only as translated TLA+.
- **SANY-style precedence conflicts** (`parse/lower/prec.rs`): tree-sitter accepts any combination, SANY rejects operators with overlapping precedence ranges that compete for one operand (`a /\ b \/ c`, `a = b = c`, `UNCHANGED x'`, `[]x = 1`, ...). The check follows SANY's operator table and `OperatorStack` rules on the tree, and also corrects a few cases where tree-sitter and SANY parse differently (`~(x) = y`, a prefix operator before a parenthesised operand).
- A file may hold several modules. `parse/sexp.rs` prints the AST as an s-expression (tests, `examples/parse.rs`).

### 3.2 Semantic analysis (`tlx-sema`, replacing SANY)

1. **Module loading** (`resolve/modules.rs`): starting at the root module through `EXTENDS`/`INSTANCE`. Search order follows TLC's `SimpleFilenameToStream`: the root module's directory, `-I` directories, `TLX_PATH`, the bundled standard modules (`tlx-sema/modules/stdlib/*.tla`), the bundled CommunityModules (`tlx-sema/modules/community/*.tla`), then `TLX_CLASSPATH`.
2. **Standard modules and native overrides.** Standard modules are parsed as ordinary TLA+; definitions are overridden by native `Builtin`s keyed by (module name, definition name) (`builtins.rs`; the equivalent of TLC's Java overrides, effective whichever way the module was found). Natives exist for Naturals, Integers, Sequences, FiniteSets, TLC, TLCExt, Randomization, Bags, Json and for part of the CommunityModules listed in `COMMUNITY_NATIVE_MODULES`. `Reals` has no natives (as in TLC its placeholder definitions are evaluated); the remaining community operators are evaluated from their TLA+ definitions.
3. **Name resolution** (`resolve/`) produces the HIR (`hir.rs`): identifiers become `Var / Const / Local / Apply{OpRef::Def|Const|Param|Builtin}`. It handles LET, bindings in quantifiers/CHOOSE/set comprehensions/function constructors (tuple patterns included), higher-order parameters, LAMBDA, RECURSIVE, LOCAL, transitive EXTENDS exports, `I!Op` and parameterised instances `I(p)!Op`. Modules, EXTENDS and INSTANCE disappear in the HIR.
4. **INSTANCE** is clone-and-substitute: `INSTANCE M WITH c <- e` resolves M's definitions in a child context, M's CONSTANT/VARIABLE references are replaced by the instantiating expressions (implicit substitution for same-named symbols); a parameterised instance gives every definition extra leading parameters. Modules that declare nothing (the standard modules) always live in the root context and are resolved once. Substitutions of an INSTANCE inside LET may refer to LET locals, outer parameters and bound variables.
5. **Subexpression selectors** (`resolve/subexpr.rs`, SANY's Subexpression algorithm): `D!1!2`, `D!:`, `D!lab`, `!<<`, `!>>`, `!(args)`, labels with parameters. A selected subexpression becomes a synthetic definition memoised by (definition, normalised path); selection inside a binding construct lifts the bound variables to extra parameters.
6. **SANY-style checks.** `Program::load` resolves and checks *all* definitions of all modules, not only those the model uses.
   - Scope and arity (`resolve/names.rs`): define before use (RECURSIVE excepted), multiply-defined symbols and shadowing, redefining builtins, import conflicts (same kind and arity: a warning and the first wins), arity, INSTANCE substitutions only for declared symbols and once each, no duplicate record fields, no cyclic module dependencies.
   - Levels (`resolve/level.rs`, SANY's `levelCheck`): constant / state / action / temporal; definitions are summarised the way SANY does (level, per-parameter weight, maximum allowed level per parameter, minimum acceptable level of operator parameters). Instantiated definitions are checked on the substituted HIR.
   - cfg level checks (`check_cfg_levels`, TLC behaviour): an INVARIANT that is not a state predicate gives exit code 76; a PROPERTY with an action-level non-temporal part gives 151.
   - Error texts follow SANY where practical (`tests/sany.rs` compares with SANY's messages).
7. **Validation.** `scripts/sanydiff.py` compares SANY's and tlx's accept/reject verdicts on every `.tla` in the corpus (`tlx-sema`'s `examples/check.rs`). Remaining differences are listed in [compat.md](compat.md).

### 3.3 `.cfg` parsing (`tlx-front::cfg`)

Follows TLC's `ModelConfig`: `CONSTANT(S)` (`c = v`, `c = [M] v`, `F <- G`, `F <- [M] G`; values are integers, strings, booleans, model values, finite sets), `INIT`, `NEXT`, `SPECIFICATION`, `INVARIANT(S)`, `PROPERTY/PROPERTIES`, `CONSTRAINT(S)`, `ACTION_CONSTRAINT(S)`, `SYMMETRY`, `VIEW`, `ALIAS`, `POSTCONDITION(S)`, `CHECK_DEADLOCK`. As in TLC, commas are not accepted. Also `_POSSIBLE`, `F(args) = value` and operator symbols in substitutions; a `.tla` file's `---- CONFIG Name ----` section (`config_section`). Extensions (TLC rejects them): negative integers, tuples, `F(_, _) <- G`. Deviations: string escapes are decoded; internal keywords such as `_PERIODIC` are parsed and ignored (see the module comment of `cfg/mod.rs`).

With `SPECIFICATION Spec`, `tlx-eval/src/model/spec.rs` splits `Init /\ [][Next]_vars /\ WF.../SF...` into Init, Next and the temporal conjuncts (fairness etc.). A PROPERTY is split into: state predicates (checked on initial states only; TLC's implied-init, with TLC's state-level warning), `[]P` (checked as an invariant), `[][A]_v` (an action property), and the remaining temporal part (liveness, §7.4).

## 4. Semantics that must match TLC

These points decide whether differential testing passes. [tlc-semantics.md](tlc-semantics.md) has the details with TLC source references; this is the summary.

1. **Integers.** TLC uses 32-bit ints; `+ - * ^` and unary minus raise an error on overflow; `%` with divisor <= 0 and `0^0` are errors; `\div` is bound per module (floor when EXTENDS Integers). tlx computes in `i64` and range-checks every operation against i32 (`tlx-value/src/arith.rs`; `tlx_add` etc. in the generated C's `runtime.h`). An integer literal outside i32 gives TLC's "TLC can't handle a number this big". There is no `--int64` relaxation.
2. **Total order of values** (set normalisation, `CHOOSE`, printing): sets compare by size then elementwise; functions by domain then values; records by field names then values. **Strings and model values compare by intern order, not lexicographically**: values appearing in the cfg first, then identifier tokens in SANY's parse order, then string literals (in semantic-analysis order), finally strings created at run time. tlx builds the same intern table (`intern_cfg`/`intern_sources` in `tlx-eval/src/interp/cfg.rs`; module order from `Program::sany_file_orders` mimics SANY). Untyped model values sort before everything else. Comparison dispatches on the *left* operand's class, so it is asymmetric as in TLC (`tlx-value/src/order.rs`).
3. **CHOOSE** normalises the set and takes the least satisfying element; unbounded CHOOSE is an error.
4. **Type errors in equality.** `1 = "a"` and `<<>> = {}` are errors; an untyped model value compared with anything else is FALSE; "typed" model values (names of the form `x_...`) compared with a non-model-value or another type are errors.
5. **Functions, records, sequences, tuples.** A tuple equals a function with domain `1..n`, a record a function over a set of strings. `tlx-value` keeps canonical forms (domain `1..n` is a `Tuple`, a non-empty string domain a `Record`), so structural equality is semantic equality and fingerprints agree. Exception: functions TLC builds over an enumerated domain (`[k \in {1, 2} |-> e]`, `:>`, `@@`, Bags, elements of `[{1, 2} -> S]`) stay `Fcn` (`FcnKind`) even when the domain is `1..n` or a set of strings: comparison, hashing, fingerprint and printing treat them as the equal `Tuple`/`Record`, but EXCEPT and application look keys up by equality (a model-value key is not in the domain, so EXCEPT returns the function unchanged where tuple/record would raise). A function over an interval `lo..hi` with `lo # 1` is an `Fcn` with `FcnDom::Interval`: non-integer keys are errors (TLC's `FcnRcdValue` with `intv`). `FcnDom` does not take part in comparison, fingerprints or encoding; the compiled tier infers it from the keys when decoding (compat.md D-13).
6. **Init/Next enumeration.** Only `x' = e` with `x'` unassigned on the left is an assignment; `x' \in S` enumerates; `x' \subseteq S` enumerates the powerset; `\A` in action position unfolds into a conjunction (so it can assign; `\/` and `\E` produce duplicate successors); CASE takes the first true arm; a nested `[A]_e` adds a stuttering successor; `UNCHANGED x` or a conflicting `x'` prunes the branch; once all variables are assigned the remaining conjuncts are predicates (Init and Next alike); lazy function applications in actions are unfolded; conjuncts are processed in written order; the intermediate states of the outermost action composition `\cdot` of a step count as generated (TLC does not count those of nested compositions or of compositions under ENABLED); a variable an operand leaves undetermined keeps its value in the intermediate state (compat.md D-19).
7. **Enumeration order** (affects CHOOSE and early-stop counts): SUBSET by size then lexicographically; `[S -> T]`, `\X` and record sets vary the last component fastest; `\E x, y` varies the first variable fastest. A lazy `S \cup T` or `UNION` enumerates duplicates, giving duplicate successors that count as generated. The lazy/eager choice replicates TLC's `Reducible` logic (comment in `tlx-value/src/ops/mod.rs`).
8. **Deadlock.** A state is deadlocked when expansion produces *no* successor at all; successors equal to the state itself, already seen, or violating a constraint do not count. `CHECK_DEADLOCK FALSE` or `-deadlock` disables the check.
9. **Counting.** Successors violating CONSTRAINT/ACTION_CONSTRAINT count as generated but are neither distinct nor queued; invariants and action properties are checked at every generation (invariant first); successors whose evaluation failed (error, VIEW failure) are counted as generated before the check (TLC `Worker.addElement`).
10. **Order-sensitive cases.** VIEW, SYMMETRY on a spec that is not truly symmetric, TLCSet/TLCGet, random numbers and early stop on an error make results depend on exploration order. With one worker tlx reproduces TLC's action and enumeration order; with several workers level-synchronous BFS keeps depth and shortest counterexample identical (§7.3), but run-time statistics such as `TLCGet("stats")` are only approximate.

## 5. Interpreter (`tlx-eval`, `tlx-value`)

It serves as (a) the `-interp` tier, (b) the constant evaluator and pre-run observer of the compiled tier (§6.5), (c) the fallback of the compiled tier at (state, action), predicate and expression granularity, and (d) a second oracle for differential testing. Its target is TLC-identical semantics with performance no worse than TLC's interpreter (it is faster on most models with one worker).

### 5.1 Values (`tlx-value`)

`Value = Bool | Int(i64) | Str(Sym) | ModelValue(Sym) | Set(Arc<[Value]>) (sorted, no duplicates) | Interval(lo, hi) | Tuple | Record | Fcn (key-ordered pairs) | LazySet | LazyFcn`. Lazy sets (SUBSET, `[S -> T]`, `\X`, record sets, `Seq(S)`, lazy `\cup`/`\cap`/`\`/UNION, filters over non-enumerable bases) expand on demand by TLC's rules; lazy functions (infinite domain, recursive definitions) live in `tlx-eval/src/lazy.rs`. `Interval` and `LazySet` compare and fingerprint as the set they denote. Printing (`fmt.rs`) reproduces when TLC expands a lazy set.

**Interning** (`intern.rs`): a global string table; the order of a `Sym` is its first-intern order (§4, item 2). Reads are lock-free with a per-thread lookup cache.

**Fingerprints** (`fingerprint.rs`): a value is serialised into a self-delimiting stream of 64-bit words (sets in canonical order) fed to a two-lane folded-multiply hash. Strings use a precomputed text hash, but record fields, set elements and function domains are hashed in their canonical order, which for strings is intern order: **a fingerprint is stable within a process and comparable across processes only with the same intern order** (recover restores the checkpoint's string table before anything else interns; `tlx-value/tests/sym_order.rs`, the `CkRec` case of `tlx-cli/tests/checkpoint.rs`). The compiled tier's word fingerprints (atom indexes into intern-ordered universes) depend on it in the same way. Fingerprints need not equal TLC's FP64. An interpreter state's fingerprint combines the per-variable fingerprints (`combine_fps` in `model/symmetry.rs`); a variable whose representation a successor shares with its parent reuses the parent's canonical form and fingerprint (`same_rep` in `model/mod.rs`).

### 5.2 Evaluation and enumeration

- **Environment** (`env.rs`): a persistent linked list; each `LocalId` is unique per binding site so recursion finds the innermost binding. Bounded quantifiers rebind in place, intervals iterate lazily.
- **Init/Next enumeration** (`enumerate.rs`): walks conjuncts in order over a partially assigned next state, branching on `\/` and `\E`, with continuations on the stack, and checks at the end that all variables are assigned.
- **Action splitting** (`Interp::split_actions`, TLC's `getActions`): follows `\/`, LET, `\E` over constant ranges and user operators whose arguments are all constant-level, yielding action instances with an environment. They label traces (`A(1)`), drive per-action statistics, `-coverage`, the action choice of `-simulate`, and the compiled tier's action granularity. As in TLC, instantiated definitions with substitution are not expanded further (`Action.at` is the INSTANCE statement), `\E` over an empty set is an action without successors, and an operator application with non-constant arguments is named after the operator.
- **`-generate`**: with `Enumerator.random`, disjunctions, `\E`, `x' \in S`, `x' \subseteq S` are tried in random order and the first feasible choice is taken (TLC's `Tool.probabilistic`).
- **ENABLED** is evaluated by enumerating until one successor is found, reusing the current state's definition memo.

### 5.3 Caches and argument passing

- **Definition classes** (`interp/analysis.rs`, fixpoint on the call graph): constant-level, action-level (observes the next state), side-effecting or non-deterministic (TLCGet/TLCSet, RandomElement, JavaTime, Print/PrintT and their transitive users), cacheable per state (0-ary, state-level, deterministic, not LET), and recursive function definitions.
- **Constants.** Constant-level 0-ary definitions are evaluated once (`const_cache`). CONSTANT values, cfg bindings and the constant cache are deep-copied per thread (`interp/local.rs`) to avoid reference-count contention between workers. The enumerated domain of a quantifier (including `\E` in actions) or set map `{e : x \in S}` whose bound set is a closed constant expression (`Interp::is_closed_constant`: no bound variables, parameters or LET definitions, constant-level and deterministic) is cached per thread (at most 2^14 elements, `Interp::bound_elems`), e.g. `\E p \in Seq(Nodes)` or `SUBSET Nodes` inside an operator body. In constant contexts (ASSUME, constant definitions, cfg; no state) applications of constant-level, value-parameterised, non-LET operators are memoised per thread by (definition, argument values compared by representation) in `memo.rs`: arguments must be small non-lazy values, results small, errors are never memoised, and definitions with a low hit rate stop being memoised. TLC does not memoise; results are identical.
- **Lazy function memo and effects.** Recursive functions and kept-lazy lambdas retain pure memo entries across compiled restarts. Entries whose bodies may perform effects register a weak memo invalidation with the effect journal: full/pre-run rollback removes those entries, and level rollback removes only entries evaluated in the interrupted level. Dry interpreter checks discard new effectful entries immediately. Startup evaluations made before journaling remain cached.
- **State-level memo** (`StateMemo` / `DefCache` in `eval/context.rs`): different contexts of one state (invariants, actions, properties) share one memo (the thread keeps the last 4 states, `MEMOS` in `model/mod.rs`). During enumeration the successor is incomplete, so only unprimed evaluations are memoised.
- **LET**: a 0-ary LET definition is evaluated at most once per evaluation of its LET (`Binding::LetCache`).
- **Filters over sequence sets** (`tlx-eval/src/seqfilter.rs`). `{s \in [1..n -> R] : P}` (the base may also be the union of function sets `[1..k -> R]`, as in a bounded `Seq(R)` replacement) where `P` reads `s` only through `s[i]` (index not depending on components), `Len(s)` and `DOMAIN s`, and components enter only comparisons, integer arithmetic and boolean operations (through non-recursive definitions): `P` is evaluated on a *prefix* in three-valued logic. When the prefix decides `P`, all extensions (contiguous in enumeration order) are skipped or produced wholesale; otherwise components are extended one at a time (`ops::for_each_enumerated_seqs` hands the whole function set to the filter). This is sound because for each length `P` is first evaluated with all components unknown, which walks every branch a sequence could take and tries every possible value of unknown operands for every operation; if no error is possible (index out of range, type mismatch, overflow, non-boolean operand), TLC's left-to-right short-circuit evaluation gives the same result as the three-valued evaluation and the order equals the base set's enumeration order. Otherwise, or if `P` is outside this form, elements are evaluated one by one. On a sorted-sequences test model (5 values, length up to 8, 480,000 sequences) the initial-state computation dropped from 0.72 s to 0.06 s.
- **Argument passing.** Only arguments of action-level operators are passed by name (so `x' = e` through an operator parameter is still recognised as an assignment); the others by value, to avoid exponential re-evaluation. Within a program a by-name argument is `Binding::Name(ExprId, Env)` pointing into the HIR arena built by sema and owned by the `Program`, without touching shared reference counts; expressions synthesised or rewritten so that they no longer match the arena become an owning `Binding::Thunk`. Reading an index borrows the `Program`; there are no raw pointers or unsafe lifetime conventions. Deferred error arguments in lazily evaluated modules use the same path.
- The interpreter scales across workers (mimalloc global allocator, no shared counters).

### 5.4 Model layer (`tlx-eval/src/model/`)

- **`InterpModel`** implements `Model` (§7.1): Init and action instances, invariants, CONSTRAINT/ACTION_CONSTRAINT, action properties, implied-init, ASSUME, POSTCONDITION (evaluated after the search; `TLCGet("stats")` sees the final statistics), ALIAS (traces are shown through the ALIAS record), trace action labels (`<A(1) line 6, col 3 to ... of module M>`).
- **SYMMETRY** (`model/symmetry.rs`): computes all non-identity elements of the generated permutation group (group closure). The orbit representative is the state of the orbit that is least in TLC's value order, comparing the variables one by one; the state's fingerprint is that of the representative. With a VIEW the variables are compared in TLC's order of the state's values (the print order, `print_order::tlc_var_order`), as TLC does (`TLCStateMut.fingerPrint`), since which member's VIEW is taken decides the counts; without one any canonical member will do, and they are compared from the smallest (`size_order`: sizes are the same in the whole orbit, and small variables usually decide cheaply). `Group::least_perm` finds the permutation giving it without building permuted states: a permutation is compared with the least so far variable by variable, stopping at the first that differs, and `cmp_images` compares the images of two values under two permutations component by component as `cmp_tlc` would compare the built images (the same comparisons, results and errors): tuples and records position by position, functions and sets element by element in the order of their images, which is the original order when the permutation maps the model values among the keys (`Server`-indexed functions), otherwise found by selecting the least remaining image as far as the comparison needs (`ImageOrder`; the least state's orders are kept across permutations). Permutations that act on the model values occurring in the state like the identity or an earlier one are skipped. Only the winner's changed variables are built (`FastPerm::apply`, sharing unchanged subvalues; `ops::permute_shared`).
- **VIEW**: the fingerprint is that of the VIEW value. **VIEW + SYMMETRY** follows TLC: take the least state of the orbit as above (`least_in_orbit`), then evaluate its VIEW.
- **Undeclared symmetry** (`model/autosym/`, `model/symcheck.rs`): the analysis behind the default mode's automatic symmetry (§2.6). For each CONSTANT whose cfg value is a set of model values, `autosym::candidates` proposes the permutations and `autosym::analyze` / `analyze_guarded` prove, under the bounds and bounded checks of [reductions.md](reductions.md) section 2.4, which of them the spec is invariant under; the CLI either prints the suggestion or applies the proven group to the search after a bounded cross-check. `symcheck` is the declared-symmetry path of `-checksymmetry`: it looks for a genuine violation of a declared `SYMMETRY` within the given state and depth bounds, so an inconclusive run is never reported as a proof. The user-facing contract is [usage.md](usage.md) sections 6.1–6.3.
- **Variable print order** (`model/print_order.rs`): TLC prints variables in the reverse of the enumeration order of SANY's symbol table (a Java `Hashtable` keyed by name). tlx rebuilds that table (the 72 builtins, the symbols of every EXTENDS, this module's units) and replays the insertions to obtain the same order.
- **Liveness obligations** (`model/liveness.rs`): §7.4.
- **Native operators**: `builtins.rs` (TLA+ core and standard-module overrides, including the TLCGet/TLCSet registers, `TLCGet("level"/"config"/"stats"/"spec"/"action"/"revision")`, Assert, Print, CSV/IOUtils side effects) and `natives.rs` (CommunityModules definitions that cannot be evaluated directly, such as graph connectivity, `atoi`, `IOEnv`).

## 6. Compiled tier (`tlx-layout`, `tlx-compile`, `tlx-native`)

Enabled with `-compile`. Sections 6.1 to 6.5 together are "the compiled tier over encoded states".

### 6.1 Pipeline

```
InterpModel
 → (1) static hints: atoms and integers in the cfg, constant ranges/integer sets, string literals of the spec (speculate/static_hints.rs::hints)
 → (2) pre-run: a bounded interpreter BFS (state/time budget) observes each variable and joins the values into a Shape;
        it also observes "materialization candidate" definitions and the VIEW definition (speculate.rs::prerun_shapes)
 → (3) headroom (infer.rs::Observer::finalize), unify records with equal field names → one Shape per variable → fixed-size Layout (tlx-layout)
 → (4) lowering: Init, every action instance, invariants, action properties, constraints, liveness atoms → typed IR (lower/)
 → (5) background: IR → C → cc → dlopen (enc/native.rs); until it is ready the IR executor / interpreter runs
 → (6) search (tlx-runtime, model = EncModel); any (state, action) that errors is re-run by the interpreter
 → (7) a successor outside the layout = layout miss: stop, widen the Shape, go back to (3), resume from the failing level when possible (§6.5.3)
```

### 6.2 Shapes and encoding (`tlx-layout`: `shape.rs`, `layout.rs`)

A `Shape` statically describes a value precisely enough to give it a fixed-length encoding. The encoding is **canonical**: for one shape `encode(a) == encode(b)` iff `a == b`, and unused words are 0.

| Shape | Encoding (`u64` words) |
|---|---|
| `Never` | 0 words (no value observed yet) |
| `Bool` | 1 word, 0/1 |
| `Int{lo, hi}` | 1 word holding `v - lo`; out of range = miss |
| `Atom(U)`: finite universe of model values / strings in TLC order | 1 word, index into U |
| `Set{elem, max_card}` with a countable element universe of at most 4096 (`MAX_BITSET_UNIVERSE`) | bitset; bit r = the element of rank r is in the set (rank order; compound elements containing sets may need TLC ordering at iteration time). More than `max_card` elements is also a miss (compiled unions, constructions and shape changes check the cardinality, `lower/sets.rs::card_checked`; otherwise a state could transcode differently from a fresh encoding when the layout is widened) |
| `Set{elem, max_card}` with a larger universe | `len` plus `max_card` elements in encoding-lexicographic order, zero padded; exceeding = miss |
| `Fcn{dom, range}` with a compile-time-known finite domain (`1..n` or all strings when built over an enumerated domain, §4 item 5; tuples/records and such an `Fcn` convert into each other when encoding, `shape::fit_repr`; a join of both is a `Map`) | the values' encodings in domain order |
| `Map{key, range}`: the domain varies over a subset of the key universe (bags, functions on `0..n`, functions built with `:>`/`@@`) | presence bitmap over the key universe plus one range slot per key (0 when absent); at most 4096 words (`MAX_MAP_WORDS`) |
| `Record{f: s}` (fields in `Sym` order) | field encodings concatenated |
| `Tuple(s1..sn)` | components concatenated |
| `Seq{elem, max_len}` | `len` plus `max_len` slots, zero padded |
| `Union(arms)` (values of different kinds, e.g. records with different fields; at most 8 arms) | arm index plus that arm's encoding (padded to the widest arm) |
| tuple arms of a `Union` (distinguished by length, e.g. `<<>>` and `<<node, round>>`): tuples of different lengths join into a `Tuple` arm sorted by length if every non-empty tuple's components belong to distinct kinds (positional types) and there are at most 4 lengths, otherwise into a `Seq` (a sequence grown by repeated Append passes through length 1, so it stays a `Seq`) | as `Union`; arms sorted by length, which is TLC order |
| `Dyn` | 1 word: the low 3 bits are a kind tag; strings, model values (by `Sym` number), booleans and integers within 61 bits are encoded in the handle, other values are handles into a global interner (`dynval.rs`) sharded 64 ways by hash, one lock per shard; canonical within one run |

`layout.rs` provides `encode`/`decode`/rank/unrank. A state is the concatenation of the variables' encodings, a `[u64; W]`. Equality is word comparison; the fingerprint is `tlx_fp_words` (host `tlx_native::fp_words`, same algorithm as the C side).

### 6.3 Typed IR and lowering (`tlx-compile`: `ir.rs`, `lower/`)

- **Statements.** An action instance (or Init) lowers to a continuation-passing statement tree (`Stop / Emit / Branches / Guard / Let / ForEach / Assign / Repeat / Error ...`) with **exactly the TLC enumeration semantics of `tlx_eval::enumerate`** (`lower/stmt.rs`): assigned next-state variables are tracked statically along the continuation; `\/` duplicates the continuation (total size bounded by `STMT_BUDGET = 20000`); `Emit` sits exactly where the interpreter would produce a successor; TLC's quirks are kept (duplicate successors from overlapping disjuncts, the "all assigned" shortcut, `\A` unfolding, lazy function construction, by-name arguments). An action that cannot be lowered with identical semantics is marked `Unsupported` as a whole and left to the interpreter.
- **Action composition.** `Compose` lowers both operands as independent partial actions and keeps a continuation for each possible assignment mask of the second operand. The closure executor fills missing intermediate variables from the original current state, merges compatible final assignments, and runs the continuation in the original state context (compat.md D-19). Captured temporaries retain their values across the state change; state caches do not. Intermediate counts commit only after successful compiled execution and are suppressed during paranoid cross-checks. C and JIT currently delegate composition to this executor; it may retain individual interpreter expressions without interpreting the whole action.
- **`\A x \in S : B` in actions.** If B neither assigns nor branches: a single guard. If it branches but does not assign: `Repeat` (count B's successful paths per element, and run the continuation the product of those counts). If it assigns and S is a compile-time constant: static unfolding. Otherwise the interpreter takes over. "Branches/assigns" is judged by statement position only.
- **Expressions.** Every IR expression has a representation type `Ty`: `Bool`, `Int` (i64 with i32 overflow checks), `Enc(shape)` (state variables stay layout-encoded), `Val` (a boxed `Value` using the value library's operations). Lowering prefers typed fast paths (`lower/typed.rs`, `select.rs`, `sets.rs`, `member.rs`, `maps.rs`, `fold.rs`). Target-driven construction (`construct.rs::expr_into`) builds records, tuples, sequences, bitsets, constant-domain functions, Maps and `MapSet`s directly into the target encoding. A subtree that cannot be specialised becomes `ExprKind::Interp` (decode the needed variables, call the interpreter, encode the result); in native code this is a host *region* ([mixed-mode.md](mixed-mode.md)). Lowering is always typed (`Lowerer::with_typing`). Shape ids are interned on demand and constant shapes reuse already interned ones (the order is observable, so it must stay stable when code moves).
- **Encoded set iteration.** `OrderedSet` keeps records and tuples containing scalar-universe bitsets encoded while enumerating in TLC order (`encoded_order.rs`). A shared prefix comparison plan orders sets by cardinality, then their least differing element; record/tuple fields are compared recursively, and compatible union arms follow their tags. Sorted-array sources sort indices rather than rewriting their canonical encoding. Finite bitset sources use precomputed rank-to-order keys and sort only the present ranks. C, JIT and the IR executor follow the same plan; unsupported or potentially incomparable shapes remain boxed. Order-independent quantifiers retain encoding-order iteration.
- **Constant folding.** Closed constant-level subexpressions (constant LETs and constant local quantifiers included) are evaluated by the interpreter at compile time into literals and cached. **Non-deterministic or side-effecting builtins (Random*, TLCGet/TLCSet, Print, JavaTime, CSV/IOExec, ...) and their users are never folded** (`tests/volatile.rs`). A constant `\E` in action position is not folded (it would change the duplicate-successor count). Expressions that may create strings are not folded either, because strings are ordered by creation order; the decision is described in §6.5.1 (folding uses the variable-agnostic typed analysis `StringMakers::typed`, so `Tail`, `SubSeq` and `\o` on sequences of numbers still fold).
- **Recursion.** RECURSIVE operators and recursive function definitions compile to function calls when the parameters can be typed (`lower/calls.rs`). Otherwise (a RECURSIVE operator inside LET, untypeable parameters) the recursion is unrolled linearly to `RECURSION_UNROLL = 6` levels; deeper calls and self-calls of non-linear recursion become `Interp` nodes (host regions), so the whole action does not fall back.
- **ENABLED** in the IR is a statement tree run on a temporary next state (supported by the IR executor and C).
- **In-place update** (`inplace.rs`). Updates of encoded values (EXCEPT chains, nested paths `![a].x`, sorted-array insertion chains, bitset union/intersection/difference) are computed straight into the target according to an `inplace::Plan` (the next-state slot of an `Assign`, or the update expression's own buffer): the base value is copied once, each update writes only its slot, a LET temporary whose value is an update points at the target directly, and values the target already holds on the path (the `f[a]` of `![a].x`) are not copied again. A plan is generated only when legal: an expression evaluated after a write must not read a temporary that lives in the target, was bound and then written (that subtree falls back to evaluating the whole value and copying). C, JIT and the closure executor run the same plan; `Assign` does not save/restore the next-state slot (words of unassigned variables are never read). `x = c1 \/ x = c2 \/ ...` with adjacent, consecutive constants merges into a range comparison (`lower/mod.rs::int_ranges`).
- **Post-lowering passes** (`lower/regions.rs::hoist_typed`, `lower/cse.rs`). Typed loop invariants in strict positions of binding constructs (each conjunct of a `CHOOSE` body) that themselves contain a loop or call (like `Max(S)` in the body of `PreviousLeader`'s `CHOOSE`) are hoisted before the construct and computed once when the source is non-empty (also for compiled function bodies). Repeated element ranks in one expression (`RankFlat`/`RankUnion` over temporaries or variable slices) are computed once, bound before the smallest subexpression containing all occurrences.
- **Debugging.** `TLX_IR_DUMP=name` prints compact IR (`ir_fmt.rs`; `TLX_IR_DUMP_RAW` prints the Debug form); `TLX_COVERAGE=1` prints typed coverage and a histogram of boxed nodes (`coverage.rs`, `enc/diag.rs`).

The typed IR has a common compile-time verification boundary (`verify.rs`). After
lowering and its optimizations, `verify::Program` borrows the complete program
immutably and checks the state layout, shape references, operand/result types,
encoding slices and widths, concatenations, index spans, sequence/set capacities,
union and recoding tables, lexical temporary scopes, function signatures and
state assignment scopes. C and JIT accept this proof rather than raw function
lists; model closure compilation consumes the same proof. Standalone closure
compilation entry points perform the same checks before constructing closures.
Host regions are checked when extracted, before generating their ABI calls; their
input/result representations and assigned-state context are verified and their
table is immutable afterwards. The verifier does not execute expressions or
change TLC error ordering: runtime conversions and speculative layout misses
remain runtime events. Raw encoding fragments used for concatenation are checked
for width, not interpreted as independent TLA+ values.

Verification failure is a compiler defect. Debug and unit-test builds and
paranoid mode fail hard; a release diagnostic switch can request the same policy
([configuration.md](configuration.md)). Normal release discards the model's
compiled functions and executes the interpreter, preserving the existing tier 1/2
contract. Rejecting the entire compilation unit also rejects any caller of an
invalid recursive function. A malformed extracted region rejects its native
function. Verification runs only during compilation, including layout-miss
recompilation; there are no checks in the per-state execution path. Statistics
report IR lowering and IR verification separately.

Builtin properties are declared with each registration in `tlx-sema/src/builtins.rs`:
`Builtin::metadata()` provides arity, effects/startup caching, string creation,
and strict/special/operator-argument evaluation. The interpreter's typed string
analysis refines this shared classification for the actual operand types.

Compiled function dependencies have one graph walker and fixed point in
`lower/summary.rs`. Each immutable function summary carries memo read sets,
effects (including the output-only distinction), state-buffer requirements,
recursion, operator-argument captures and ENABLED. `summary_hir.rs` supplies
fallback read sets through environments, LET definitions and operator arguments.
Memo reads and required state buffers remain distinct: ENABLED owns its next
buffer, while an unknown memo read set disables memoization. Lowering, region
planning and native planning share cached summaries; mutable typing access and
recursive-attempt transitions invalidate both the summary and verification
caches. The verifier reuses lowering's state-buffer contracts; standalone IR
inputs use the same graph engine with a context-only provider.

### 6.4 Predicates, materialization, SYMMETRY, VIEW (`enc/model.rs` and its `checks`, `codec`, `fingerprint`, `liveness`, `symmetry` and `view` children)

- **Fallback and executors.** Three executors (closure IR, Cranelift JIT, C) and the order in which they are tried are in §6.6; functions the closure compiler does not cover are treated as not lowered and go to the interpreter. `exec/mod.rs` keeps shared state, memo tables and the call budget; `exec/words.rs` only the bitset operations used by the closures. The number of fallbacks is reported as bailouts at the end of the run.
- **Predicates and properties.** Invariants lower to `PredFn`; `[A]_v` / `<A>_v` in PROPERTY and ACTION_CONSTRAINT lower to transition predicates (`v'` reads the successor); CONSTRAINT is an extra single-state predicate; liveness state atoms and action atoms are compiled as extra native invariants/action properties (§7.4).
- **Definition materialization** (`lower/materialize.rs`). A 0-ary, state-level, deterministic definition referenced by an invariant/action property (or VIEW) that is cheap to evaluate in the pre-run gets a speculated shape; the predicate computes it once at its start in dependency order (primed and unprimed separately) and binds it to a temporary. Scalar-valued definitions (usually the invariant itself or a conjunct) are not materialized: if the pre-run sees a scalar after 50 evaluations it stops evaluating the definition (evaluating a heavy invariant such as a snapshot-isolation check per state can take half the pre-run). A value outside its shape makes this predicate fall back to the interpreter and records a "definition miss"; after widening the model is recompiled (`TLX_NO_MATERIALIZE` disables). Definitions that may create strings are not candidates (evaluating them in every pre-run state would create strings early); the decision uses state-variable types (`StringMakers::for_states`, §6.5.1).
- **SYMMETRY.** One `PermPlan` is compiled per group element and variable (`tlx-layout/src/permute.rs`: atom lookup, bitset bit-order mapping, re-sorting after permuting a sorted array, moving slots of an atom-domain function, moving presence bits and slots of a Map, `Dyn` permuted by value and re-interned; positioned shapes are flattened into word-level copy/map segments). The fingerprint is that of the **encoding-lexicographically least state of the orbit**; variables are compared from narrowest to widest encoding with early exit, because narrow variables are cheap and often reject a permutation first (`orbit_fp` in `enc/model/symmetry.rs`, with thread-local buffers). (Any canonical member of the orbit gives TLC's counts without a VIEW.) A `Dyn` handle's image under a plan is memoized per thread (`DYN_MEMO`: handles are never reused). Shapes that cannot be permuted fall back to decoding and fingerprinting by value.
- **VIEW.** The VIEW definition (once its shape is speculated; components of a tuple VIEW that are state variables take the variables' layout shapes, `Dyn` included) is compiled as a single-action small library over an extended layout; the fingerprint is that of the VIEW encoding (native → IR → interpreter). **VIEW + SYMMETRY** (`Fingerprint::SymView`, TLC semantics, §5.4): the orbit's least state is chosen by value (`InterpModel::least_perm`, decoding variables only as they are compared), its encoding is permuted with that element's `PermPlan`s, and the VIEW encoding of the result is fingerprinted. Without permutation plans or a compiled VIEW it takes the by-value path.
- **Init** runs natively or in the IR; when the IR is running a large Init and the native library becomes ready, the IR run is aborted and restarted natively.

### 6.5 Speculation, guards and recompilation (`enc/speculate.rs`, `enc/driver.rs`, `tlx-layout/src/infer.rs`)

#### 6.5.1 Pre-run

- A bounded interpreter BFS, budgeted by `TLX_PRERUN` distinct states (default 20,000) or `TLX_PRERUN_MS` (default 1000 ms); the initial states (up to the state budget) are exempt from the time budget. CONSTRAINT/ACTION_CONSTRAINT are honoured as in the search: states are observed when generated but only states within the constraint are expanded.
- **Stop when the layout settles** (`TLX_PRERUN_SETTLE`, default 2000). When a state changes the observed shapes, tlx checks whether it still fits the layout chosen from the earlier observations (using the same procedure as the search: headroom, type-invariant bounds, record unification). If not, it records the number n of states observed so far and re-chooses the layout. When another max(2000, 2n) states have been observed and the layout kept fitting, the BFS ends (initial-state enumeration never ends early). When the interpreter is slow the time criterion also counts as settled: at least 50 ms of **CPU** time (`tlx_base::time::process_cpu`, all threads) have passed since that state and at least twice the CPU time it took to find it, and at least 500 (a quarter of the count) fitting states were observed. CPU time, not wall time: the wall clock stretches with the machine's load without the pre-run observing more, so a loaded machine settles early (EWD998PCal under load settled after 1565 states instead of 4938 and needed 3 layout restarts instead of 1); CPU time scales with the observation work itself, and with several pre-run threads it still does (states observed scale with the work, not with the wall time it takes). The default is a trade-off: relative to 5000 it cuts instruction counts and total time on the corpus, with one model getting slower (two more layout misses at depth 19-21); 1000 saves slightly more but costs more misses on another model, and late misses in big state spaces are expensive while the pre-run time saved is at most about 0.1 s. Relaxing the doubling factor (waiting for 9n states) was tried: it catches one more late shape but only lengthens the pre-run elsewhere and widens layouts (more headroom from larger observations) without ever reducing misses overall, so the rule stays. The price of settling early is that a rare shape appearing later becomes one layout miss (resume: re-encode the visited states, about 2.5 us/state).
- **Parallel pre-run.** With `-workers N`, a non-faithful pre-run (below) whose search creates no strings and evaluates no volatile builtins (random, TLCGet/TLCSet, Print, CSV, IOExec; `search_is_volatile`) runs its BFS level by level in parallel: each level's states are split across N threads, each with its own observer, merged at the end of the level (settling is judged on the merged observations). Faithful pre-runs, simulation pre-runs and initial-state enumeration stay single-threaded.
- **Faithful pre-run** (when the search may create strings, `search_makes_strings`). Run-time strings are ordered by creation order, so the pre-run's evaluation sequence must be a prefix of the one-worker search's. It therefore **is the search** (`faithful_prerun`): a one-worker `explore_observed` with the quiet observer `Faithful`, which sees every state the search checks (new states and every generated state outside the constraint) and stops the search at the budget (`SearchObserver::stop`: only the state budget during initial states, afterwards state, time and settling budgets; when it stops after a successor, the state being expanded does not process its remaining successors, nor its stuttering step or state atoms). Constraints, deduplication, invariants, init properties, action properties, liveness atoms (`Caps::live_atoms`), symmetry reduction, `TLCSet("exit")` and the `TLCGet` statistics come from the search itself, not from a hand-copied reimplementation (which drifted before). Differences from the search: it does not stop at deadlock (states behind a deadlock are unreachable for the search and do not affect its string-creation order; but see "pre-run as the search" below); an error generating states (Init, Next or the states it yields) fails the pre-run, while a checking error merely stops; liveness atoms are evaluated only when they may create strings (`live_makes_strings`; the pre-run never builds a behavior graph, and evaluating atoms in the interpreter can cost more than the rest of the pre-run).
- **"May create strings"** (`tlx-eval/src/strings.rs`, `strings/types.rs`). `ToString`, JSON/CSV/IOExec and similar builtins always may; `Tail`, `SubSeq` and `\o` create strings only when applied to strings. The pre-run therefore uses `StringMakers::for_states`: a small type inference over the state variables with the domain "may be a string" (Top) or "not a string, and its parts (function/sequence/record values, set elements) have type t", truncated at 6 nesting levels. It collects the `=`, `\in`, `\subseteq` assignments to `x'` (to `x` in Init) in Init (unassigned variables), every action instance (with the by-name arguments of its environment), constraints, invariants, action properties, VIEW and liveness atoms (assignments under ENABLED included) and takes the least fixpoint; definitions are expanded at each application with the argument types, recursive definitions reuse their analysis when the argument is covered by an outer application and are otherwise analysed once for an arbitrary argument. Only when an operand may be a string do those three operators count as creating strings. If the analysis cannot follow (assignment to or application of an opaque parameter, expansion beyond 2^20 expressions) it falls back to a purely syntactic judgment, so the answer is always conservative; the syntactic judgment also looks at by-name arguments bound in the expression environment and at LAMBDAs. The same analysis decides materialization candidates (by state-variable types) and constant folding during lowering (`StringMakers::typed`: ignores variables, treating each as possibly a string). Constant definitions evaluated in TLC's order at startup (`Interp::eval_constant_defns`: pure constant definitions are evaluated eagerly only if they may create strings, otherwise at first use) use `StringMakers::typed` too. Effect on the corpus: 26 models no longer need a faithful pre-run (the remaining ones really create strings, e.g. by calling IOExec); across them the instruction count geometric mean fell to 0.85 and one string-heavy model went from 1.31 s to 0.40 s. The price: a few tiny models that previously used the faithful pre-run directly now compile and then search (about 0.05 s more each).
- Without faithful mode and with SYMMETRY, the pre-run does not reduce by symmetry (too expensive in the interpreter, and observing more permuted values is better); VIEW is kept (otherwise the state space may be unbounded).
- **Pre-run as the search** (`TLX_PRERUN_REUSE`, default on, off under `TLX_PARANOID`). If a faithful pre-run finishes within budget (not stopped by `Faithful::stop`: it exhausted the state space or stopped at a violation, deadlock or evaluation error), its report is exactly what the interpreter, the compiled tier's semantic oracle, reports for the same search, and is used directly as the run's result (`enc::Checked::Interpreted`; the CLI completes the report, liveness and `-dump` on the interpreter model) without lowering, code generation or search. The precondition is "the same search": one worker, no `-coverage`, no `-spill always`, a growable fingerprint set (the pre-run uses the search's growable set, so it fills at the same time), neither the search nor liveness atoms evaluate volatile builtins (the pre-run's output, registers, files, external commands and random choices are undone), the search would not have taken a checkpoint by the time the pre-run ends (`Checkpointer::would_be_due`), the same deadlock check; when the search records a behavior graph the pre-run must also have recorded one (atoms may create strings), in which case the quiet pre-run still reconstructs failing traces and builds the graph (`SearchObserver::complete_results`). Only faithful pre-runs can be used this way: a non-faithful pre-run only generates states, without checking invariants, properties or deadlock and without traces, and making it check for the chance of exhausting would cost (interpreter checks per state) more than the compiled search saves (about 10x faster per state). On the corpus this applies to a dozen models with a few hundred to a few thousand states, each saving 0.02-0.05 s. Consequence: such small specs do not execute compiled code under `-compile`; compiled-code coverage is provided by `TLX_PARANOID` (no reuse) and `TLX_PRERUN_REUSE=0`; the test helper `enc::check` never reuses.
- Otherwise the pre-run result is used only to speculate shapes. Pre-run evaluation may write the TLCGet/TLCSet registers; they are restored to their pre-run values before the search. A `TLCSet("exit", TRUE)` evaluated in the pre-run stops the pre-run and is undone when it ends (also on rerun and resume); the search triggers it again itself.
- A failed pre-run (evaluation error) makes all variables `Dyn`; the search reports the error.

#### 6.5.2 Headroom (`infer.rs`)

- Integer ranges include 0, the upper bound gains `max(2, 50%)` (negative ranges likewise), clamped to i32 (`widen_int`).
- Set `max_card` and sequence `max_len` become `max(2n, n + 2)` (a set never exceeds its element universe). Bitset-encoded sets that are not themselves elements of another set take the universe size: the bitset word count is independent of `max_card`, which only serves the cardinality check, and a growing set (a message set) would otherwise miss and restart repeatedly; sets that are elements of sets keep `max(2n, n + 2)` (it determines the outer set's universe and ranks). When widening turns a full bitset into a sorted array (universe above 4096), `max_card` is re-chosen from the missing value. A bound that a layout miss grew gets the same headroom (§6.5.3).
- Atom universes absorb the hint atoms of the same kind (cfg model values / spec strings); a *typed* model value (`T_x`) only absorbs hint model values of its own TLC type (`infer.rs::extend_atoms`), because TLC refuses to compare two typed model values of different types: a field that holds one type is not a field that holds another one, and stating otherwise would make the field's shape unusable for every encoded set of records with that field. When the pre-run observes an atom universe holding 1024 or more *computed* strings (not hint atoms) it turns it into `Dyn` directly (`Observer::observe_with`; the enclosing union or Map becomes `Dyn` as a whole): such a universe is open, every new string would force a new layout, and the cost grows with the universe size.
- Records with the same field names are unified across all variables and materialized definitions (`unify_records`), so a value moved between variables is encoded identically.
- **Type-invariant bounds** (`speculate.rs::type_bounds`). A conjunct `x \in S` / `x \subseteq S` of an INVARIANT (through 0-ary definitions) with `S` a side-effect-free constant set gives an upper bound for `x`'s shape from `S`'s structure (`SUBSET`, `[S -> T]`, record sets, `\X`, `Seq`, `\cup`, ... without enumerating; `infer.rs::set_elem_bound`). The bounds refine the pre-run observation (`infer.rs::refine`): a set takes the element shape of the bound (adding unobserved union arms; same-named non-integer fields of union arms joined; integer ranges and atom universes take, in turn, "union with the observation", "bound for atoms", "bound for both", whichever is the loosest within twice the words of the smallest, so as not to disagree with other variables' encodings) if that lets it become a bitset with fewer words (e.g. `msgs \in SUBSET Message`: sorted array becomes bitset); for sorted-array sets the cardinality and for sequences the length are the smaller of the two; value-position integer ranges widen to include the bound; everything else is unchanged. After record unification the bounds are used only if the state word count does not grow (`driver.rs::with_bounds`). A value outside the bound violates the invariant: first a layout miss (widen, resume), then the violation is reported.

#### 6.5.3 Layout miss, widening, resume

- **Guards.** Every encoding operation that writes state checks the value against the shape (integer range, atom universe, set universe/cardinality bound, sequence length, domain, record fields, type). A failure is a **layout miss**: the first (variable, value) is recorded and the search stops with an error.
- **Widening** (`driver.rs`, `infer.rs::widen_repeated`). The missing value widens its variable (headroom only for the part that changes). A set `max_card` or sequence `max_len` that the miss grew doubles like an observation (`max(2n, n + 2)`, `infer.rs::grow_len`). A smaller step (the value's cardinality plus `max(n - bound, n/4, 4)`) was tried and reverted: it shrank the layouts that overshot (MultiPaxos_MC_small `msgs` 24 -> 31 instead of 50, 321 instead of 473 state words; instructions within 4% on the 22 small models with misses), but a value that keeps growing with the depth misses again later, in a larger search, and once the archive is over `TLX_RETAIN_MB` that restart starts over: MultiPaxos_MC (37M states) widened `msgs` to 31, missed again at 32 after 15.8M states and expanded 54M states instead of 37M (1.45x the CPU time at every worker count). An overshooting bound costs a few words per state; an undershooting one can cost the whole search so far. On the k-th miss of a variable (k from 0, k >= 1), growing integer ranges in value positions (not set elements or Map keys) first expand on the growing side by span x 4^k, then get the usual headroom. An atom universe that grows by strings becomes `Dyn` when it already contains computed strings (e.g. results of `ToString` or `\o`) or the variable already missed twice (an open string universe would miss for every new value; the enclosing union becomes `Dyn`); model values join all cfg atoms of their kind (a typed one only those of its own type, §6.5.2) at once and never become `Dyn`. Integers that had the same bounds (counters, indices, copied values) widen together (`widen_alike`), then records are unified again. A miss of a materialized definition widens that definition, and materialization is dropped if the result contains `Dyn`. At most 16 restarts (`TLX_MAX_RESTARTS`); the last restart makes the missing variable `Dyn` and un-materializes the missing definition. If restarts run out and it still misses, the log says so and the run **falls back**: all variables `Dyn`, nothing materialized (it cannot miss again; actions run through boxed IR / interpreter), completing the run from the failing level (or from scratch) instead of failing.
- **Resume, not restart.** While a miss is still possible the explorer keeps expanded states (bounded by `TLX_RETAIN_MB`, default 1024; scale.md describes the archive). After a miss it rolls back to the start of the failing level (statistics and the out-degree histogram as at the level start, `tlx_runtime::ResumePoint`), transcodes states to the new layout variable by variable (identical shapes copy, integer ranges shift, the rest re-encode through values; `enc/model/codec.rs`), recomputes fingerprints and continues the BFS from that level. Transcoding runs in parallel on the search workers; it does not evaluate the interpreter (no VIEW, no by-value fingerprints) and with at least 10,000 states uses max(workers, min(cores, 8)) threads; the result is independent of the thread count. Counts, depth and trace equal the uninterrupted search. (Example: a miss at depth 21 that transcodes 259,000 states drops from 0.59 s to 0.09 s with parallel transcoding.) With more than 1000 states it first trial-transcodes a sample of 1000: if a state does not fit, or the extrapolated transcoding time exceeds re-running the search so far, it restarts from scratch; so it does when the retention budget is exceeded or the model has `\cdot` intermediate-state counting (`Model::extra_generated`).
- **Side effects** (`tlx-eval/src/interp/effects.rs`). A rerun/resume re-evaluates what was evaluated after the interruption point, but output, files and registers must equal an uninterrupted run. When a restart is still possible the interpreter keeps a log: each worker marks the start of a new level (`Effects::mark`, saving its registers) and saves its registers at the end. On resume, workers that took part in the interrupted level (`ResumePoint::rolled_back`) treat the lines they printed in that level as "owed": evaluating a line with identical content again prints nothing (matched by multiset of content; with one worker the order is the interpreter's order); files written in that level are restored to their state at the level start (the file contract below); each worker continues from its registers at the level start (at the level end if it did not take part), not from the main thread's. On restart from scratch, all lines printed so far are owed, files are restored to their state before the run and registers restored to their pre-run values. Simulation restarts (always from scratch) work the same way, and files written by the pre-run are restored. A search interrupted by a miss does not reconstruct a trace (`Effects::interrupts`; reconstruction would evaluate and print again). IOExec (and IOEnvExec, IOExecTemplate, ...) cannot be undone, so it is accounted: while a restart is possible each execution's result is recorded (keyed by hash of operator and argument values, in order); rolled-back executions' results are "owed" and re-evaluating the same command takes the owed result instead of executing again; at the end of the pre-run the same rollback happens (its executed commands' results are owed to the search that follows; with one worker the pre-run's states are a prefix of the search's), so under `-compile` commands execute as many times as in the interpreter and TLC (`tests/resume_effects.rs`, `ioexec_runs_once_after_restart`). With several workers commands are matched by command, like printed lines (compat.md D-15).
  - **File effect contract**: every native writer declares `FileWrite::Append` or `FileWrite::Overwrite` through `Interp::with_file_write` before modifying a file. `Append` may only extend the file (CSVWrite/CSVWriteRecord); its undo record holds the original length. `Overwrite` may replace existing bytes (JsonSerialize/ndJsonSerialize); its undo record holds the original bytes. A file absent at the checkpoint is removed on rollback. Before the first overwrite, any earlier append-only records for the same path are upgraded to byte snapshots of their original prefixes, in both the run and worker journals. Thus append/overwrite mixtures and repeated rollbacks restore the correct content. When workers share a path, rollback selects the earliest recorded write among the rolled-back workers, using write order rather than minimum length. Native writers validate and serialize values before entering the journal; evaluating a lazy value may itself print or write files. Only the final byte write and its snapshot share the journal lock, so their recorded order is the actual write order across workers without locking around nested evaluation. Byte snapshots are held in memory while the run can restart. Preservation errors reject the write; restoration errors stop the compiled run, including after the pre-run, instead of continuing from damaged files. These guarantees concern writes managed by this interface; IOExec commands remain non-undoable and replay their recorded results as described above. Dry interpreter checks suppress writes. Regression coverage: `crates/tlx-cli/tests/resume_effects.rs` checks reads, verdicts, counts, depth and final bytes for shorter/equal-length JSON and newline-delimited JSON overwrites, with level resumption, full restart and pre-run rollback, nested writes during lazy serialization, and fatal restoration failures; `interp/effects.rs` tests mixed append/overwrite and cross-worker checkpoints.

- A rerun/resume uses a fresh set of worker threads: POSTCONDITION sees the registers of worker 0 of the last run.
- **After the search there are no restarts** (`EncModel::restartable` is cleared). In later phases (liveness counterexample reconstruction and edge recording for the levels before the resume point, the `-dump` search) a materialized definition whose value does not fit its shape is evaluated by the interpreter for that atom instead of counting as a miss; a phase that still hits a layout miss (`tlx_compile::enc::is_layout_miss`) is redone by the interpreter as a whole: liveness is checked by the interpreter (the interpreter model searches itself, records the behavior graph, then checks; VIEW/SYMMETRY still use the TLC-algorithm path) and `-dump` rewrites the file with the interpreter. POSTCONDITION and ALIAS are evaluated by the interpreter on decoded values and never miss. Tests: `tlx-cli/tests/live_miss.rs`, `tests/specs/LVM1`/`LVM2`.

#### 6.5.4 Simulation and generation

- `-simulate -compile` (`enc::simulate`): the pre-run spends at most about a quarter of the time on BFS (stopping when the layout settles, §6.5.1) and the rest on random behaviors to observe deep states. It stops once half of the elapsed time (at least 50 ms) has passed since the last state that did not fit the current layout, so `TLX_PRERUN_MS` is used up only if the shapes keep changing. On a miss it widens and **reruns the whole simulation with the same seed** (side effects accounted as in §6.5.3). Handing only the missing behavior to the interpreter is not done: once the encoded state cannot hold the value, the rest of that behavior consists of interpreter states, which needs a model mixing both kinds of state or a simulator that can resume at a behavior boundary (per-worker RNG state, shared counters, behavior-level side-effect marks); simulation misses are already rare after the pre-run has observed random behaviors.
- `-generate -compile`: state encoding, invariants and so on use compiled code, but action successors are computed by the interpreter (its random choices are TLC's probabilistic evaluation; a compiled action enumerates all successors).

#### 6.5.5 Verification

- **`TLX_PARANOID=1`** (`-compile`): every compiled (state, action) result is compared as a multiset with the interpreter's successors (raw values, ignoring VIEW and counting), and the lines a compiled action printed with the interpreter's (as a multiset); the compiled Init with the interpreter's Init; native invariant/constraint/action-property verdicts with the interpreter's; SYMMETRY permutation plan results with by-value permutation; native VIEW encodings with the interpreter's; resume transcoding with fresh encoding. An interpreter error where compiled code yields successors is also a mismatch. A mismatch panics at once: a worker panic stops the search, breaks the level barrier, the main thread joins and re-throws, and the process exits with 101 (`tlx-runtime::explore`; test `tlx-cli/tests/paranoid.rs`, which injects wrong results with `TLX_INJECT_MISMATCH=drop|dup|stale|init|inv[:n]`; `miss` injects a layout miss where restarts are impossible). `TLX_PARANOID` implies a synchronous native build.
- **Encoding round trip**: `cargo test --release -p tlx-testkit --features interpreted,values --test layout_corpus -- --ignored` checks `decode(encode(v)) = v` and `encode(a) = encode(b) iff a = b` on the pre-run states of corpus models.
- Three-way differential testing (TLC / interpreter / `-compile`): §8.2.

### 6.6 Executor tiering

One typed IR has three executors, with the interpreter as semantic reference and fallback.

| Tier | Code | State representation | When it runs |
|---|---|---|---|
| Interpreter | `tlx-eval` (`InterpModel`) | `Value` | `-interp`; in the compiled tier (the default) the pre-run, functions that are not lowered or not pure, `-generate` actions, every fallback; traces, POSTCONDITION and ALIAS are evaluated on decoded values |
| Closure IR executor | `tlx-compile/src/exec/fast/` | encoded words | the native library is not ready yet (the background build with `TLX_JIT=0`), `TLX_NO_NATIVE`, a function that is not native; the host of mixed-mode regions |
| Cranelift JIT | `tlx-compile/src/jit/` (cargo feature `jit`, default on) | encoded words, same ABI as C | default `TLX_JIT=tier`: compiled within milliseconds after the model is built, so exploration starts out native |
| C | `tlx-compile/src/cgen/` → `cc` → `dlopen` (`tlx-native`) | encoded words, ABI v5 (§6.7) | background `-O2` build, replaces the JIT library when loaded, or loaded directly on a cache hit; its code is 4-25% faster than the JIT's (`enc/native.rs`) |

- **Call order** (`enc/model.rs`): Init, actions, invariants, CONSTRAINT, ACTION_CONSTRAINT, action properties, liveness atoms and VIEW are each tried native → closure IR → interpreter. Native and IR runs are speculative: results go to a buffer, and any problem (runtime error, intermediate value outside the layout, `TLX_UNSUPPORTED`) discards the buffer and the interpreter re-runs that (state, action) or predicate; the interpreter has the final say on errors and counts. An action goes through the IR only if it has no interpreter-fallback node (`exec_ok`: crossing into and out of the interpreter node by node is slower than interpreting whole), Init only if it does not evaluate side-effecting builtins (a failed run would repeat the side effects). `TLX_PARANOID` compares each compiled result with the interpreter (§6.5.5).
- **Native plan** (`native_plan.rs`). The C generator is the reference backend. At generation time it decides which functions are native and which subtrees become host regions (`RegionBuilder`), producing a `NativeSet` and the region table. The JIT reads the same plan and calls the same regions at the same call sites (`RegionCursor` checks that each region is called exactly once). If the JIT's `NativeSet` differs from the plan or a region is not reached, the JIT is not enabled (log `JIT disabled: ...`) and C is used. The two libraries are therefore interchangeable at run time.
- **Mixed mode** (default on, `TLX_MIXED`; [mixed-mode.md](mixed-mode.md)). Boxed subtrees C cannot compile become regions evaluated by the host's closure executor through `host->eval` (`HostRegions` in `enc/mixed.rs`; the handle arena and the state-decode cache are in `tlx-native/src/mixed.rs`); pure regions are memoised by input (`exec/memo.rs`); `enc/adapt.rs` compares, per mixed function, the running time of mixed native code and whole-function fallback online and uses the faster.
- **Shared runtime core.** Sorted-array set membership, insertion, union/intersection/difference and the combination enumeration of `SUBSET` are implemented once, in `exec/encops.rs`: the closure executor calls it directly, the JIT through thin `extern "C"` wrappers in `jit/rt.rs` (the C side is `cgen/runtime.h`); the JIT's `pow`/`gcd` call `tlx_value::arith`. The state fingerprint `tlx_native::fp_words` and the JIT's inlined `fp_words_ir` are both tested against the reference implementation in `tlx_abi.h`.
- **Tiering and background build** (`enc/native.rs`). With `TLX_JIT=tier` (default) the JIT runs first; the C `-O2` library is built and loaded on a background thread only after the search has run for `TLX_CC_DELAY_MS` (1.5 s), so short runs do not pay for `cc` (on macOS the first `dlopen` of a new dylib alone costs about 0.4 s: syspolicyd has XProtect scan every new executable). When ready it replaces the JIT code; if `cc` fails the JIT stays. A run that ends before the delay and whose JIT compile took at least `TLX_CC_AT_EXIT_MS` starts the C build in the background at exit, so that the next run hits the cache. A model that a layout miss *discards* is the other case: its library could never be loaded, so the driver stops the running compiler (and a delayed one never starts) instead of letting one large translation unit per attempt compete with the search (`cancel_builds`, `Build::wait_or_cancel`). `TLX_JIT=1` (or `only`) uses the JIT only. `TLX_JIT=0` uses C only: until the C library is ready the search runs on IR / interpreter (same results), and a source of at least 256 KiB without a cache entry first gets a quick `-O0` build replaced by `-O2`. `TLX_NATIVE_SYNC` (implied by `TLX_PARANOID`) builds synchronously, `TLX_NO_NATIVE` uses IR only, `TLX_CGEN_DEBUG` reports why a function is not native. The C build is a separate `sh` child process and is placed in the cache atomically; concurrent tlx runs share one build (`TLX_CACHE` in [configuration.md](configuration.md)).
- **Verification.** Executors are compared by the testkit's differential tests (`tlx-testkit/src/diff.rs`; `TLX_JIT=1 TLX_JIT_VERIFY=1 cargo test --profile test-release -q -p tlx-compile --features tlx-testkit/jit`, see [testing.md](testing.md)); the tier as a whole by `TLX_PARANOID`; `TLX_MIXED_FORCE=k` forces regions in an all-native spec to exercise the ABI ([mixed-mode.md](mixed-mode.md)).

### 6.7 C code generation and the native ABI

**Decision.** The host (front end, compiler, runtime) is Rust; the per-spec specialised code is generated as **C** (`tlx-compile/src/cgen/`), compiled by the system C compiler (`$CC` or `cc`, clang on macOS) into a dynamic library that `tlx-native` loads with `dlopen`. Reasons: clang shares LLVM with rustc, so code quality is comparable while compilation is an order of magnitude faster than building Rust; C is the easiest to generate; and the narrow ABI means a JIT could be swapped in without touching the runtime (which is how the Cranelift tier was added).

- Fully typed, C-compatible functions are generated as native code; functions with boxed nodes also become native in mixed mode (default), calling host callbacks for the boxed regions (`eval`/`elems`/`mark`/`release`, ABI v3 onward, [mixed-mode.md](mixed-mode.md)); function bodies that still cannot be generated return `TLX_UNSUPPORTED`. Representation: `Bool`/`Int` are `int64_t`; encoded values are `const uint64_t *` into the state, a static constant or a function-local buffer; boxed values are host value handles (`uint64_t`). Expressions use GCC/clang statement expressions; integer operations use `runtime.h`'s `tlx_add`/`tlx_mul`... with i32 range checks.
- Run-time problems (overflow, an argument outside the domain, a value outside the layout) return `TLX_ERR`: the host discards that call's successors and the interpreter re-runs it (§6.6). A successor outside the layout calls `host->miss(var)` / returns `TLX_MISS`.
- **Cache.** Keyed by an FNV hash over (C source, ABI header, compiler, options), in `$TLX_CACHE` or `~/.cache/tlx/<hash>/model.{dylib,so}`; a build writes a temporary name and renames atomically, so concurrent processes are safe. (Lowering and C generation are redone each run; only the `cc` output is cached.)

#### ABI (`crates/tlx-native/src/tlx_abi.h`, `TLX_ABI_VERSION 5`)

```c
#define TLX_OK 0
#define TLX_STOP 1    /* emit asks to stop */
#define TLX_ERR (-1)  /* runtime error, already reported through host->error */
#define TLX_MISS (-2) /* layout miss, already reported through host->miss */

typedef struct tlx_ctx tlx_ctx;            /* host-private per-call context */
typedef union { int64_t i; const uint64_t *w; uint64_t h; } tlx_arg; /* region argument: scalar / encoding / value handle */
typedef struct {
  int  (*emit)(tlx_ctx *cx, const uint64_t *state, uint32_t action); /* host copies the state; nonzero = stop */
  void (*error)(tlx_ctx *cx, uint32_t err_id);                        /* index into error_msgs */
  void (*miss)(tlx_ctx *cx, uint32_t var);                            /* a value does not fit variable var's layout */
  /* v3: mixed mode, boxed regions are evaluated by the host (docs/mixed-mode.md) */
  int  (*eval)(tlx_ctx *cx, uint32_t rid, const uint64_t *s0, const uint64_t *s1,
               const tlx_arg *args, uint64_t *out);                  /* evaluate region rid; TLX_OK / TLX_ERR */
  int  (*elems)(tlx_ctx *cx, uint64_t set, uint32_t sorted, uint64_t *first, uint64_t *n); /* elements of a set handle */
  uint64_t (*mark)(tlx_ctx *cx);                                      /* handle high-water mark */
  void (*release)(tlx_ctx *cx, uint64_t mark);                        /* free handles above the mark */
  /* v5: value store handles (experimental, TLX_VALUE_STORE, docs/value-store.md) */
  int  (*ref_op)(tlx_ctx *cx, uint32_t op, const uint64_t *args, uint64_t *out); /* operation op of the table; TLX_OK / TLX_ERR */
  int  (*ref_elems)(tlx_ctx *cx, uint64_t set, const uint64_t **first, uint64_t *n); /* elements of a stored set */
} tlx_host;

typedef struct {
  uint32_t abi_version, words, n_actions, n_invariants;
  const char *const *action_names, *const *invariant_names;
  uint32_t n_errors; const char *const *error_msgs;
  uint32_t n_regions; uint64_t regions_hash;  /* v3: number of host regions and hash of the region table (0 without regions) */
  uint32_t n_refops; uint64_t refops_hash;    /* v5: number of value store operations and hash of their table (0 without) */
} tlx_spec_info;

const tlx_spec_info *tlx_info(void);
int tlx_init(const tlx_host *h, tlx_ctx *cx);
int tlx_next(const tlx_host *h, tlx_ctx *cx, const uint64_t *s, uint32_t action);      /* one action instance at a time */
int tlx_invariant(const tlx_host *h, tlx_ctx *cx, const uint64_t *s, uint32_t inv);   /* 1 holds / 0 violated / negative = error or unsupported */
int tlx_action_property(const tlx_host *h, tlx_ctx *cx, const uint64_t *s, const uint64_t *t, uint32_t i); /* optional symbol */
```

- A state is `words` `uint64_t`s; generated functions have no mutable global state and can be called by several workers concurrently. CONSTRAINT and liveness state atoms are compiled after the invariants; ACTION_CONSTRAINT and liveness action atoms after the action properties (`EncModel` records each start index).
- On load the host checks `abi_version` and that `(n_regions, regions_hash)` and `(n_refops, refops_hash)` equal its own region and value store operation tables; when `tlx_action_property` is missing, action properties go through the IR / interpreter.
- v3 added the mixed-mode callbacks and the region-table hash; v4 removed a test-only fingerprint entry point (the fingerprint algorithm is unchanged); v5 added the value store callbacks. The header is part of the cache key, so an ABI change invalidates old libraries by itself.
- **Value store operations** (`ir::ExprKind::RefOp`, `exec/refops.rs`): the operation table numbers every distinct (operation, arity) of the verified program in a fixed traversal, so C, the JIT and the host agree on the ids; its canonical text is written into the C source (so it is part of the cache key) and its hash into `tlx_spec_info`. `ref_op` runs the store method of the same name that the closure executor calls, so all executors compute the same handles; a failing operation (a TLC error, a case the store leaves to the interpreter, a full store) makes the whole call fail and the interpreter redo it. The store itself — what a handle is, how two of them are equal, the budget and the lifetime — is [value-store.md](value-store.md) sections 2 and 6, which also owns the operation set behind these ids (section 4); this document owns the callbacks and their version.
- **Printing traces does not go through C**: the host decodes fixed-length states into `Value`s by `Layout` and prints those.
- A sanitizer build is switched on by `TLX_CC_SANITIZE=1` (`BuildOptions::debug`, ASan + UBSan; [unsafe-audit.md](unsafe-audit.md)). Batch successor return with fingerprint-set prefetching is not implemented.

### 6.8 Coverage and what remains boxed

`scripts/coverage.py` and `TLX_COVERAGE=1` report, per model, how many action instances, invariants and action properties are lowered, native and fully typed, plus a histogram of the remaining boxed nodes. On the corpus models with a report almost all action instances are lowered and native (mixed mode included), about 97% fully typed, and all invariants and action properties are native.

The remaining boxed nodes are few and rarely hot (measured as time in host regions under `-stats`; node count and run-time cost are almost uncorrelated). Structural reasons they stay boxed:

1. In actions, `\E m \in S` where `S`'s element encoding order is not TLC order (records with set fields, sets of sets) must iterate in TLC order; a precomputed rank permutation table for bitsets (a new iteration source in C, JIT and closure executor) would do, but corpus benefit is small.
2. Function sets `[S -> T]` with a dynamic domain (filters and maps over them).
3. Folds over functions with a variable domain (`Map` encoding) or with more than 64 elements.
4. Large combinatorial structures (permutation sets and the like) whose cost is in the interpreter's definition of the operator itself; they rely on memoisation.

Already native: sets-with-set-fields ranking for one-word bitsets over at most 62 elements (`lower::word_ranked_set`), static cardinality bounds that survive temporaries (`Lowerer::temp_cards`), folds (`FoldFunction`/`FoldSeq`) over fixed-domain encoded functions, records and tuples in TLC domain order (`lower::fold`), and memoisable pure fallbacks inside transition predicates, bound as separate regions keyed by input (`regions_post` → `split_memoizable`); equivalent memoisable regions share one memo node (`enc/region_eq.rs`, [mixed-mode.md](mixed-mode.md)); `DOMAIN f[x]` and `f[x]` for a binder `x` over a constant list whose elements are all in f's fixed domain (`Lowerer::iter_temp`: the application cannot fail, so the operand need not be kept for its errors); unions `{x} \cup S \cup T` of sorted-array sets, built in a shape with room for all operands (`sorted_union_into`; the singleton's own shape overflowed at run time); `(k :> v) @@ f` into a fixed-domain function when `k` is in the domain (an EXCEPT of that slot); `Max`/`Min` of encoded integer sets, sums by `FoldSet`/`MapThenFoldSet`/`SumSet` over encoded sets (`+` with operands of one sign), `SumFunction` and `IsInjective` of fixed-domain functions. Also: actions that print (Print/PrintT as host regions whose output is held until the native run succeeds, mixed-mode.md §4); `r.f` on a map over strings (records built with `:>`/`@@`, `lower::select`); `CHOOSE` over an encoded set whose encoded order is not TLC's when it has a single witness (checked at run time, `lower::choose::verified_choose`); sets of integers of unknown bounds (`{cur, F(cur + 1)}`) over all TLC integers; recursive operators whose branches are scalars (`calls::branch_types`); sequences converted element by element into sequences of another element shape.

The key universe of a map whose keys are strings does not absorb the spec's strings at `finalize` (`infer::headroom_at`; atoms inside composite keys still do): a map over strings is usually a record built with `:>`/`@@` (ext Zab_new's `recorder`: 6 keys instead of 59, 1934 instead of 2294 state words); a new key is one layout miss, whose widening absorbs the hints.

## 7. Runtime (`tlx-runtime`)

### 7.1 The `Model` trait (`model.rs`)

```rust
pub trait Model: Sync {
    type State: Clone + Send + Sync;
    fn init_states(&self, out: &mut dyn FnMut(Self::State)) -> Result<(), ModelError>;
    /// Yield successors one by one (stuttering included) with the action index; `out` returns false to stop.
    fn successors(&self, s: &Self::State, out: &mut dyn FnMut(Self::State, u32) -> bool) -> Result<(), ModelError>;
    /// Successors of one action only (simulation; the default filters `successors`).
    fn action_successors(&self, s: &Self::State, action: u32, out: &mut dyn FnMut(Self::State, u32) -> bool) -> Result<bool, ModelError>;
    fn fingerprint(&self, s: &Self::State) -> u64;                       // VIEW / SYMMETRY included
    fn check_invariants(&self, s: &Self::State) -> Result<Option<usize>, ModelError>;
    fn check_init_property(&self, s: &Self::State) -> Result<Option<String>, ModelError>;  // implied-init
    fn constraint(&self, s: &Self::State) -> Result<bool, ModelError>;                     // CONSTRAINT
    fn action_constraint(&self, s: &Self::State, t: &Self::State) -> Result<bool, ModelError>;
    fn check_transition(&self, s: &Self::State, t: &Self::State) -> Result<Option<usize>, ModelError>; // [][A]_v
    fn extra_generated(&self) -> u64;      // intermediate states of \cdot
    fn stop_requested(&self) -> bool;      // TLCSet("exit", TRUE)
    fn invariant_names(&self) -> &[String];
    fn action_names(&self) -> &[String];
    fn action_property_names(&self) -> &[String];
    fn render(&self, s: &Self::State) -> String;   // TLC style /\ x = ...
    fn caps(&self) -> Caps<'_, Self::State>;        // optional capabilities, none by default
}

pub struct Caps<'a, S> {
    pub format: Option<StateFormat<'a, S>>,         // Words(&dyn StateCodec) | Bytes(&dyn Persist)
    pub live_atoms: Option<&'a (dyn AtomBits<S> + Sync)>,
    pub effects: Option<&'a dyn Effects>,           // mark / worker_end / replaying / interrupts
    pub checkpoint: Option<&'a dyn Checkpointed>,   // files / worker_snapshot / main_snapshot / restore_workers
}
```

The methods that decide verdicts and counts (plus `coarse_fingerprint`) have no default, so none can be forgotten; models without any checks (test models, `NativeModel`) say so explicitly with `model_without_checks!()`. Optional capabilities all live in `caps()`: how states are written (`StateFormat`: encoded words or bytes, one of the two), liveness atoms, side effects across restarts/resumes (`Effects`), the checkpoint's model files and register snapshots (`Checkpointed`); the `Caps` accessors give the defaults for a missing capability.

Behavior is added to the search not by wrapping the model but by a search observer (`explore::SearchObserver`, `explore_observed`; used by `-dump`, the liveness error search and the faithful pre-run). Its hooks: `on_init` (after a new initial state passes the checks; an error stops the search), `on_new_state` (before invariants are checked, with depth and parent fingerprint), `on_edge` (for each generated successor), `on_expanded` (a buffering observer sees all successors before they are processed), `records_live_graph` (whether to record the behavior graph as usual), `stop` (polled where a sequential search checks budgets: after each new initial state, after all initial states, after each successor and after each state expansion; returning true ends the search, unexpanded states stay in the queue), `quiet` (not this run's own search, e.g. the faithful pre-run: no `-stats`, no change of evaluation-cache quotas, no trace reconstruction, no behavior graph) and `complete_results` (a quiet search still reconstructs traces and builds the graph at the end, so the report can serve as the run's result, §6.5.1). A search without an observer runs the same code: the worker's per-successor step is instantiated by const parameters, with a separate cold instance when an observer is present; the re-execution that reconstructs an error trace is not observed.

`ModelError` carries an `ErrorKind` (General, Unsupported, AssertFailed, DivisionByZero, ArgumentError, Overflow, NullPowerNull, ApplyEmptySeq, IntegerTooBig, and the internal LayoutMiss: the compiled layout was too narrow, the search stops to widen and resume, never reported as a spec error) and an `ErrorContext` (NextState, Invariant, InitialState, ...), which decide the TLC-style message code and exit code (§8.1). Models must be deterministic: traces are reconstructed by re-execution.

### 7.2 Fingerprints and the fingerprint set (`fpset/`)

- 64-bit fingerprints (interpreter §5.1, compiled tier §6.2/§6.4). A successful run reports TLC's "calculated (optimistic)" collision-probability estimate. There is no 128-bit mode.
- One open-addressing table `[AtomicU64]` with linear probing; 0 marks an empty slot (fingerprint 0 maps to 1); an insert is a single CAS, lock-free. The default table starts at 2^20 slots (8 MiB) and grows at safepoints (high-water 0.75, hard limit 0.9). With `-fpmem MiB` the table has a fixed size; when full tlx prints "The fingerprint set is full; rerun with a larger -fpmem." with the run's numbers (`Outcome::FpSetFull`) and exits with system error code 255. This is a resource limit, not a spec counterexample, so no behavior is printed. Memory comes from the OS zero-filled lazily, so a large reservation costs no physical memory until touched. Batched inserts with prefetching are not implemented.
- **Disk tier** ([scale.md](scale.md)). When the table does not fit the `-maxmem` budget, at the high-water mark the table is written at a safepoint as a sorted run (one fence per page, one Bloom filter per run) and stays in memory as a read-only old table; lookups consult the current table, the old tables and the runs (a page is read only on a Bloom hit), so the answer is exact and the rest of the search is unchanged. Runs are merged in levels in the background. With `-spill off` a full table is still a capacity error.

### 7.3 Exploration (`explore/`)

- **States are not resident**: a state is dropped after expansion. Every distinct state appends `(parent LogRef, fingerprint)` to its worker's trace log (`LogRef` = 16-bit worker number plus 48-bit index). When a violation is found the trace is reconstructed by **re-executing the model** from the initial states along the fingerprint chain. Under VIEW/SYMMETRY, reconstruction uses bounded, iterative backtracking within the logged classes to find a real behavior whose final state or step violates the reported property. The extra work happens only when printing the counterexample; search-time logging still uses the cached class fingerprints. Replay depth is bounded by the recorded path; its worst-case work is the product of the numbers of matching class members at each level, and re-enumeration can add quadratic work within a level. Only the current path and hashes of tried alternatives are retained. Runtime-dependent predicates may prevent replay (compat.md D-30); an explicit reason accompanies a genuine prefix.
- **One worker**: exact BFS (all initial states before any successor is expanded), matching TLC's counts, early stop and `TLCGet` behavior point by point.
- **Several workers: level-synchronous BFS** (`run_levels`). Each level's frontier is split in parallel: worker-local FIFO deque + global injector + mutual stealing (crossbeam), with a barrier between levels; depth and shortest counterexample equal TLC's for any worker count. **Narrow levels** (expected expansion time below the synchronisation cost of a parallel level; per-task time and sync cost are estimated online, `CostEstimate`) are expanded by the barrier leader alone as an exact BFS, over any number of consecutive levels, while the other workers wait once at the barrier. The barrier spins first (adaptive budget of 64 to 4096 iterations, doubled when the spin sufficed, halved when it had to park), then yields a few times, then parks (`thread::park`, the leader wakes workers directly one by one, avoiding serialised hand-offs through a condition-variable mutex). The last worker to arrive (the leader) prepares the next level before releasing (installs the frontier, decides narrow-level exclusivity, re-joins the safepoint on behalf of all workers), so a level needs one barrier (two when representatives are chosen). When oversubscribed (more threads than cores) each barrier costs about one reschedule of the slowest worker; on a cloud machine with 64 cores, 64 workers and 64 competing busy processes, fewer barriers made wall time 11-22% faster.
- **Representatives under VIEW/SYMMETRY** (`explore/order.rs`). When the fingerprint does not identify the state (`Model::coarse_fingerprint`), which concrete state represents a fingerprint class (checked for invariants, expanded, entered in the trace) can change the result (e.g. when VIEW omits a variable the guard reads). With one worker the first in BFS order is taken, as in TLC. With several workers the same order is selected: each candidate (a successor of a new class in this level) carries the key `(position of the parent in the level, which successor of the parent)`, and the class keeps the smallest key in the sharded table `best` (updated atomically under the same shard lock as the seen-set insert, so "in seen but not in `best`" means a class of an earlier level). Most successors are of classes found at earlier levels; they are told apart without taking a lock or writing shared memory: a per-level bit filter on the fingerprints of the classes inserted into the seen set at this level (`NewClasses`, a bit set before the seen-set insert, about 16 bits per state of the level) is read after a seen-set lookup, and a class that is in the seen set with its bit clear is dropped at once (a set bit, also another class's, takes the locked path). Locking a shard for every successor moved its cache line between the cores on each one: with KVSSafetyMedium on a 16-core x86 instance it was the largest part of the CPU time added per state from 1 to 8 workers. A worker's cache keeps the candidate it proposed when it was minimal; after the level is fully expanded (one more barrier; a worker that took a narrow level exclusively proceeds directly) each keeps those whose key is still minimal, sorts by key, then writes the trace log, checks invariants, enqueues, and corrects the parents' out-degree statistics. The position is the rank in BFS order: each worker's keepers are contiguous in its log and are noted as `(parent position, rank among that parent's keepers)`; the per-parent counts are prefix-summed on entering the next level to get the position of each parent's first child (`Positions`); the resume point carries the positions of the interrupted level. This is used only with several workers and a coarse fingerprint (without behavior-graph recording; under VIEW/SYMMETRY liveness takes the `ConcreteChecker` replay path instead); otherwise the "first inserter wins" fast path stays. `-coverage` with several workers also uses it (a new state is attributed to the action of the first candidate in BFS order); there the fingerprint is the state, the behavior graph is recorded as usual, a state's out-edges do not depend on the representative, and tableau atoms are evaluated when the level ends for the kept candidates, as with one worker when a new state is found.
- **States outside the constraints** are not added to the seen set and are checked against the invariants every time they are generated, as in TLC (each check appends a trace log entry). When the invariants are a pure function of the state (no volatile builtins) and the fingerprint identifies the state, the model gives a key (`Model::invariant_key`, the compiled tier: its fingerprint) and each worker remembers the keys it already checked without a violation in a direct-mapped cache (2^18 slots), skipping those checks and log entries (-11% instructions on a Neon ProposerAcceptor model without SYMMETRY; under VIEW/SYMMETRY hashing the state costs about what the native invariants save, so there is no key).
- **Violations**: the first failure is recorded and the stop bit of the control word set; initial states are processed on the main thread (constraint → seen set → invariants → implied-init).
- **Worker panics** stop the search immediately and release the barrier; the main thread joins all threads and re-throws (no hang). Helper pools (liveness expansion, resume transcoding, behavior-graph edge building) carry the same abort flag: after one worker panics the others return quickly, `join_pool` joins all and re-throws once (`tlx_base::par`). The process prints one line `tlx: internal error: ...` (the CLI's panic hook, without Rust's backtrace hint; with `RUST_BACKTRACE=1` the backtrace is printed) and exits with 101.
- **Resumable search** (`explore_resumable` / `ResumePoint`, `explore/resume.rs`): optionally retains expanded states (with log positions and depth); on an error stop it rolls back to the start of the failing level and returns a resume point sufficient to continue with another model over the same state space (e.g. one with re-encoded states), and the result equals the uninterrupted one. The compiled tier uses it for layout misses (§6.5.3).
- **Control word and safepoints** (`explore/safepoint.rs`, [scale.md](scale.md)). Before each task a worker reads the control word `control` (bit 0 = stop, the other bits = pending safepoint requests) and proceeds only if it is 0. A worker that sees a request stops (`Safepoint::park`), the last active worker to arrive performs the request, possibly handing work to the parked workers with `Crew::broadcast`; workers waiting at a level barrier or finished are not active (`leave`/`join`). Used for fingerprint-set growth, frontier spill and checkpoints; tests inject periodic no-op safepoints with `Options::safepoint_every` (`tlx-runtime/tests/safepoint.rs`).
- Modules: the `explore/mod.rs` facade (options, results, `Shared`, the initial states and the state machine of one search), `run.rs` (preparing a search, the initial states, the worker scope), `finish.rs` (its results and final reports), `worker.rs` (the hot path: expand a state, process successors), `frontier.rs` (task queue), `levels.rs` (level synchronisation, barriers, narrow-level exclusivity, cost estimation), `tracelog.rs` (trace log and reconstruction), `resume.rs` (retained states and resume points), `observer.rs`, `order.rs`, `edges.rs` (behavior-graph edge log), `history.rs` (trace and edge-log shards, leased per worker and indexed by stable shard id so a checkpoint and recovery with another worker count read the same directory), `checkpoint/`, `safepoint.rs`, `coverage.rs`.
- **Live statistics** (`live.rs`): workers publish their own counters for the TLC-style progress lines (first after 3 s, then every minute; `-progress` every 10 s) and for `TLCGet("stats"/"distinct"/"generated"/"queue"/"diameter"/"duration")` (installed thread-locally, not through the `Model` interface; exact against TLC with one worker, approximate with several).

### 7.4 Liveness

**Scope.** Fairness in SPECIFICATION (`WF_v(A)`, `SF_v(A)`, including `\A x \in S : WF_v(A(x))` unfolded over constants) and the temporal part of PROPERTYs (`[]`, `<>`, `~>`, `/\`, `\/`, `~`, `=>` over state predicates, action predicates `<A>_v` / `[A]_v`, temporal IF, `ENABLED`): the LTL fragment TLC checks. The safety parts (`[]P`, `[][A]_v`) use the invariant/action-property path.

**Method (offline, after a successful search):**

1. **Atoms** (`tlx-eval/src/model/liveness.rs`). Temporal formulas and fairness are translated to `tlx_live::Ltl` over atoms (the number of branches TLC derives before the search and whether a cycle condition is needed are in `tlx-live/src/normal.rs`). State atoms are state predicates and, for fairness, `ENABLED <A>_v`: when each disjunct of A is a disjunct of the next-state relation it is `EnabledVia`, derived from the `<A>_v` action-atom bits of the state's out-edges; otherwise (an action outside the next-state relation, or a sub-action with fewer constraints) `ENABLED` is evaluated per the spec as TLC does: the interpreter infers it from the enumeration of A's steps from the same state (the one the `<A>_v` action atom already performs, see "evaluation of action atoms" below), true when some step changes v (`LiveSpec::enabled_steps`); when the steps cannot be enumerated, a step has an undetermined variable or v fails to evaluate, `ENABLED` is evaluated directly; within an INSTANCE that substitutes expressions for variables, the ENABLED of WF/SF is evaluated directly on the instantiated module's own primed variables (`ExprKind::InstVar`, compat.md D-8). Action atoms are evaluated on edges (s, t). Constant subformulas are evaluated to TRUE/FALSE first (TLC `Liveness.astToLive`), a non-temporal subformula as a whole is one atom. A temporal conjunct of the specification that is a fairness condition under a constant guard, `(guard) => WF_v(A)` (the conditional fairness of the examples of the TLA+ book, as `MCInnerSerial` writes it), is that fairness condition (guard TRUE) or TRUE (guard FALSE), not an assumption of the property: TLC folds the constant too, and as an antecedent the `[]<>`s of its consequent would fall to the tableau (the `rest` of `tlx-live/src/recurrence.rs`) instead of becoming conditions of the checker.
   TLC evaluates these predicates during the search (after each state is expanded) and stops where one fails (exit code 255, 14 for `Assert`). tlx, when graph construction fails or the search was unsuccessful, reruns the search with predicate evaluation (`tlx_runtime::liveness::find_error`) to give TLC's stopping point and counts. A search that records the behavior graph has already evaluated the atoms of every expanded state and the tableau's state atoms of every newly found (in-constraint) state (`AtomBits::tableau`; TLC evaluates them when it expands the predecessor); if none failed (`Report::live_atoms_ok`), the failure is a violation (invariant, action property, deadlock) and the initial states were all expanded (depth >= 3), TLC would not have met a predicate error before stopping either, so no rerun (after an evaluation error TLC still checks that state, so it reruns). Predicate errors in simulation are reported with the behavior as TLC does.
   TLC also reports "safety-like" temporal violations in the middle of the search (the recursive `addNextState` of `LiveCheck.TableauLiveChecker`: a product node of an already expanded state reaches the tableau's accepting sink through a stuttering self-loop — the empty particle whose only successor is itself — and the solution has an error model without cycle conditions, i.e. properties like `[](p => []q)` without fairness) and stops immediately; its verdict (ahead of an invariant violation or deadlock deeper in the BFS) and counts then differ from a post-search check. For properties that may behave so (`tlx_live::reports_early`), when the search fails or liveness finds a violation, `find_error` reruns the search with one worker in TLC's order, building TLC's product incrementally (`ConcreteChecker::fired`), and reports the violation where TLC stops (counterexample: the path to that state, then stuttering).
2. **Behavior graph**, recorded during the BFS (the cost is paid only when there are temporal obligations; `Caps::live_atoms`, `tlx-runtime/src/explore/edges.rs`). When a worker expands a state it evaluates the action atoms once per edge and the state atoms once per state; bit patterns are deduplicated in a worker-local dictionary and written to a per-worker chunked edge log (source fingerprint, state bit pattern, per in-model out-edge the target fingerprint and action bit pattern, the stuttering bit pattern). After a fully successful search the log is turned into CSR (nodes numbered by worker and record order, targets translated by an open-addressing `fp → id` table, bit patterns in a global dictionary; `tlx_live::Csr`). States are not stored: counterexamples are recovered by re-executing from the initial states along the lasso path, taking "the e-th in-model successor". Product nodes are numbered in BFS order (initial-state order, fixed out-edge order per state), so counterexamples are deterministic.
   - With an early stop by `TLCSet("exit")`, as in TLC (`LiveWorker` skips unexpanded nodes) only the graph of expanded states is checked: unexpanded states merge into one sink without out-edges (not even a stuttering self-loop), through which no behavior passes. The SYMMETRY/VIEW path expands only as many states as the search expanded (distinct minus left, the first ones in BFS order; with one worker exactly those the search expanded); the others have no out-edges.
   - If an atom evaluation fails without interrupting the search, the edge log keeps the first error (`EdgeRec`; the checkpoint's edge-log header carries it too), handed to liveness through `Report::live_error` and reported directly as an evaluation error without re-exploring (the same for errors when re-expanding the levels before the resume point). There is no fallback that re-explores the state space after the search to build the graph; a check without a recorded graph is an error (it could only come from a checkpoint lacking an edge log, which a checkpoint written by the same binary never does); failing to replay a counterexample (graph and model disagree) is an internal error, and a compiled-tier layout miss during replay makes the interpreter search again, record the graph and check.
   - Each state gets a stuttering self-loop (action atoms evaluated as s→s). Successors outside the constraint do not enter the graph, but their action atom bits count toward `EnabledVia` (TLC does not consider constraints for ENABLED).
   - **VIEW/SYMMETRY.** One fingerprint stands for several concrete states and TLC's verdict depends on which concrete state is evaluated, so these runs take a path that replicates TLC's algorithm (`tlx_live::check_concrete` / `check_trace`): the negated property becomes a DNF as in TLC; `[]<>A`/`<>[]A` conjuncts (including WF/SF folded into the formula as TLC does) are cycle conditions, the rest uses TLC's particle tableau; the product is built incrementally in BFS order — tableau-node consistency is judged on each step's **successor concrete state**, cycle conditions and fairness are evaluated on the concrete state that expands the product node (and its out-edges); a product node created after its graph node was already expanded is expanded at once from that successor concrete state (TLC's recursive `addNextState`); only the first edge between two product nodes is kept; when the search expands a representative the stuttering step comes after the successors (TLC itself puts it first when expanding other states). This path stores no concrete states: after the search a BFS in TLC's order is done again (levels expanded in parallel chunks), and events (`addInitState`/`addNextState`) flow one by one into the products of all properties (`tlx_live::ConcreteChecker`; the search for solutions and error models happens at the end, per property, solution and error model in order, with the same result as checking property by property). On-demand expansion uses only the current event's states and their successors, which are dropped when the event ends; the BFS expands each level in chunks and releases an expanded state at once, moving new states out of events' successors instead of copying, so a whole level and the next are never held at once; on successors and initial states only the tableau's state atoms are evaluated (`AtomBits::tableau_bits`: TLC only judges the consistency of tableau nodes on successors), other state atoms only on expanded states. Each expanded concrete state records only "which successor of which expanded state it came from" (for initial states the enumeration index, 8 B), from which counterexample states are recovered by re-execution (`tlx_live::Conc`); product bit sets are interned as numbers and every edge costs 16 B, a node's out-edges stored contiguously when its expansion ends (a node is expanded once). Simulation mode replicates the TLC simulator's `LiveCheck1` (removing stuttering steps first; no consistency check when connecting to an existing product node). TLC's order among successors with the same fingerprint depends on its fingerprint hash, so on rare occasions TLC's own verdict changes with `-fp`.
   - Compiled tier: atoms are compiled into the C library as extra native invariants/action properties and fall back to the interpreter on failure (compared under PARANOID).
3. **Formula to automata** (`tlx-live/src/recurrence.rs`, `tableau.rs`): each temporal PROPERTY part is checked separately (the number of disjunctive branches of ¬P is used only for TLC's "Implied-temporal checking--satisfiability problem has N branches." line). Like TLC (its `OrderOfSolution`s with `[]<>` and `<>[]` conditions), ¬P is put in disjunctive normal form over its temporal subformulas (at most 64 disjuncts; beyond that, one disjunct of its top-level conjuncts), and each disjunct is split into recurrence conditions `[]<>x` (x somewhere on the cycle), persistence conditions `<>[]x` (x everywhere on the cycle) — x propositional, possibly mixing state and action atoms evaluated at one position (a state and the step leaving it) — and a rest, for which a generalized Büchi automaton is built with a GPVW-style tableau (one acceptance set per `<>p`; a one-state automaton without a rest). The conditions need no tableau states: a conjunction of k `<>[]` or `[]<>` obligations, such as one `<>[][A_i]_v` assumption per process under a `[]<>` property, would have 2^k. The construction budget includes the formula interner, obligation caches, automaton states/edges and temporary partial expansions, then the automata plus reachable products; the runtime publishes these bytes through `mem::Gauge` and checks both the remaining allocation budget and RSS.
4. **Product** (`tlx-live/src/search.rs`): per disjunct, the reachable product of the behavior graph and the automaton, built in BFS order. A product node can be on an accepting cycle only if its automaton state lies in an accepting SCC of the automaton (a cycle covering every acceptance set); other nodes are kept for reachability and the BFS tree only, and the product stores only the edges inside an accepting automaton SCC whose position satisfies the persistence conditions. *Waiting* states — initial, without literals, with a self-loop, not in an accepting SCC: the "not yet" branch of the `<>` that the negations of `~>`, `[]<>` and `<>[]` start with — pair with every reachable graph state along the graph's own steps, so their nodes are not built at all (they would copy the graph once per such state): the steps out of them enter the other automaton states from a BFS of the graph, keeping node ids in BFS order. Without its waiting states an automaton falls apart into weakly connected components (one per `~>` of a conjunction, say) whose product nodes no edge connects; each component with an accepting SCC is a *part*, built and searched on its own, so the peak memory is that of the largest part. The parts of all disjuncts run in order, up to `-workers` at once; the result is the counterexample of the first part with one, whatever the number of threads (parts after it are skipped); if the parts in progress exceed the memory budget together, they run one at a time. `-stats` reports the tableau states, the waiting states not built, the parts, and the thread-seconds of construction and search.
   **Fairness as acceptance conditions** (not in the automaton): iterative Tarjan SCCs on the product. WF: an SCC is fair if some state has ENABLED false or an edge is an `<A>_v` step. SF: the SCC has no state with ENABLED true or has an `<A>_v` edge; otherwise the enabling states are removed and SCCs of the subgraph are searched recursively (Streett-style refinement). The tableau acceptance sets and the recurrence conditions (on edges) must likewise hold within the SCC; SCC classification checks the node conditions first and reuses its buffers (most SCCs are single nodes).
5. **Counterexample.** A reachable non-trivial SCC (or a single node with a self-loop) meeting all acceptance conditions is a violation. The lasso is built the way TLC's `LiveWorker.printTrace` does: the prefix is the BFS-tree path to the SCC's start; the cycle starts there with a greedy DFS (`dfsPostFix`: conditions satisfied by nodes/edges passed are marked satisfied, edges satisfying new conditions are preferred, otherwise an unvisited successor, backtracking when needed) that collects all conditions, then returns to the start by a shortest path (`bfsPostFix`); with no conditions to collect the cycle is a stuttering step at the start. Output: "Temporal properties were violated." plus prefix and loop ("Back to state k: <A>", or "Stuttering" for a one-state loop; steps between identical states removed), and TLC's stuttering warning when there is no fairness; exit code 13.
6. **In simulation.** Each behavior is checked separately, with or without VIEW/SYMMETRY, replicating the TLC simulator's `LiveCheck1` (`tlx_live::check_trace`; ENABLED is derived from all successors of the state): stuttering steps are removed first; when connecting to an existing product node no consistency check is done; without a tableau a new node's state predicates are evaluated on the **previous** state, as TLC does. The last two points can make TLC's verdict differ from deciding on the behavior's graph (a miss, or a counterexample violating no property; `tests/specs/LZS1`, `LZS2`); tlx follows TLC. A `-depth` cutoff is treated as stuttering.

**Evaluation of action atoms.** In interpreter mode action atoms are evaluated per edge; `<<A>>_v` atoms (those of fairness and PROPERTY) are instead evaluated by enumerating A's steps once per state and looking up per edge (`LiveSpec::from_steps`): with no step limit when A's steps are steps of Next, otherwise at most 64 steps (the atom falls back to per-edge evaluation after 8 states exceed it); a variable A does not determine (it never occurs primed) matches as a wildcard; when enumeration is impossible (an evaluation error, a primed variable read before assigned) evaluation is per edge.
In both tiers, when A is a union of the model's actions (each disjunct of A is an action: the same expression in an environment with the same bindings; `LiveSpec::label_actions`), A's steps from a state are the successors these actions generate, so the edge recorder evaluates the atom only on steps generated by one of A's actions; on a step generated by another action it holds only if one of A's actions generates the same successor (the same fingerprint) from the same state, and then as on that step (`tlx_runtime::ActionMasks`, resolved when the state's expansion ends). The compiled tier, which evaluated every action atom natively on every step, mostly evaluates one or two per step then. Not under VIEW or SYMMETRY (states with the same fingerprint differ there).

**Code layering.** The algorithms are in `tlx-live`. The spec-dependent parts (atoms, formulas, fairness, the interpreter's `AtomBits`/`SearchAtoms` implementation) are in `tlx-eval/src/model/liveness.rs`. The model-independent orchestration is in `tlx-runtime/src/liveness/`: checking a recorded graph and replaying counterexamples (`recorded.rs`), the concrete-state BFS replicating TLC for VIEW/SYMMETRY (`concrete.rs`, node table `tlx_base::hash::FpMap`), the on-demand expansion of that BFS (`expand.rs`, the model-generic runtime side of the `Expand` trait that `tlx-live`'s TLC-algorithm path calls), checking one behavior in simulation (`trace.rs`), searching once more to find errors and violations TLC reports during the search (`search.rs`, via `SearchObserver`), counterexample shape and naming the violated property (`shape.rs`). The spec is passed as a `LiveInput` (properties, individual properties, fairness, whether VIEW/SYMMETRY) and the result is a `LiveResult`; the liveness RSS guard is `tlx_runtime::mem::RssGuard`. "A successor is in the model" (ACTION_CONSTRAINT judged after CONSTRAINT holds) is defined only by `tlx_runtime::admits`, shared by search, simulation and liveness, each caller deciding explicitly whether an error propagates or counts as "not in the model". The CLI (`tlx-cli/src/live.rs`) only builds `LiveInput` and renders counterexamples (with the stuttering warning). The behavior graph on disk is in [scale.md](scale.md).

**Validation.** `tests/specs/L1`-`L12` (including violations) with expectations from TLC; every corpus model with a temporal PROPERTY agrees with TLC; `tlx-live/tests` (handwritten cases, random comparison with brute-force lasso enumeration, a scale test `TLX_LIVE_SCALE`).

### 7.5 Random simulation and `-generate` (`simulate.rs`)

As TLC's `Simulator` / `SimulationWorker`: all initial states (duplicates included) are counted and checked against invariants and CONSTRAINT in turn; a behavior starts at a random one that satisfies CONSTRAINT. At each step a random action is tried first, then the others in random step order, until some action has a successor satisfying both CONSTRAINT and ACTION_CONSTRAINT; every successor of the tried actions counts as generated and is checked in turn against invariants, action properties, CONSTRAINT and ACTION_CONSTRAINT; the next state is chosen at random among those that pass. With no feasible successor the behavior ends (deadlock is reported when checked). Each worker generates `num` behaviors (unlimited by default) of length `-depth` (default 100, `-1` unlimited), seeded by `-seed`. `-generate` is the same, but the choices inside an action are random and the first feasible successor is taken (§5.2). `TLCGet("config").mode`, live stats (traces included) and `TLCSet("exit")` work as usual; output matches TLC ("Running Random Simulation with seed ...", "The number of states generated: N").

### 7.6 `-dump` (`dump.rs`)

`-dump file` writes all reachable distinct states (`State n:` blocks); `-dump dot[,actionlabels][,colorize] file` writes GraphViz. Apart from fingerprint values the output is byte-identical to TLC's. It is implemented as the search observer `DumpObserver` (§7.1): a state is recorded before invariants are checked, its level is its parent's recorded level plus one (with several workers the VIEW/SYMMETRY representatives chosen at level end fix the level by depth), and transitions are written when successors are generated.

### 7.7 Memory, disk, checkpoint

[scale.md](scale.md) is the full design. One memory budget `-maxmem` is shared by all components, each counting in a `mem::Gauge` registered with the budget (`tlx-runtime/src/mem.rs`); under pressure the archive, trace log, liveness edge log, the encoded-level queue and the fingerprint set are written to disk in turn (`-spill`, `-maxdisk`, `-metadir`; implemented in `fpset/`, `queue/` and `io/`). Checkpoint / `-recover` (`explore/checkpoint/`; the synchronisation policy and the directory commit protocol `DirCommit` are in `io/durable.rs`) writes the fingerprint set, queues, trace log, archive, liveness edge log and (in compiled mode) the Shape / `Dyn` interners to the metadir at BFS level boundaries; after recovery the verdict, counts, depth and counterexample length equal an uninterrupted run.

**Not done:** sharding the fingerprint set by high bits bound to NUMA nodes and routing successors by fingerprint. The development machine (Apple Silicon) is UMA, so it could not be validated.

## 8. Compatibility and testing

### 8.1 TLC compatibility

- **Command line.** Options named like TLC's keep TLC's semantics (`-deadlock` means *disable* the deadlock check); [configuration.md](configuration.md) lists them, [features.md](features.md) compares with TLC's options.
- **Output** (`tlx-cli/src/out.rs`, `main.rs`): version/mode lines, "Starting...", "Computing initial states...", "Finished computing initial states: ...", progress lines `Progress(D) at ...: N states generated (X s/min), ...`, "Model checking completed. No error has been found." with the collision estimate, statistics, "The depth of the complete state graph search is D.", average out-degree, "Finished in ... at (...)", with TLC's date format. Error-trace states and action labels, ALIAS, POSTCONDITION failures, implied-init violations, false ASSUME, initial-state evaluation errors ("While working on the initial state") and invariant evaluation failures ("Evaluating invariant X failed.") follow TLC's text. `-compile` additionally prints `compile:` diagnostic lines ([usage.md](usage.md)).
- **`-tool`**: each message is wrapped as `@!@!@STARTMSG <code>:<class> @!@!@ ... @!@!@ENDMSG <code> @!@!@`; message codes are those of TLC's `tlc2.output.EC`, classes those of `MPRecorder` (0 none, 1 error, 3 warning, 4 state); evaluation errors map by `ErrorKind` to codes (Assert 2132, division by zero 2179, overflow 2178, ...).
- **Exit codes**: TLC's `EC.ExitStatus`, one constant per status (`tlx-cli/src/report.rs`; table in [usage.md](usage.md)). tlx's own: 101 = internal panic (including a `TLX_PARANOID` mismatch), 2 = usage error.
- **TLCGet/TLCSet**: per-worker registers (`TLCSet(i, v)` / `TLCGet(i)`), `"level"`, `"config"` (simulation parameters included), `"stats"` and its fields (live during the search, final in POSTCONDITION), `"spec"` and `"action"` (records and source positions as in TLC, `tlx-eval/src/model/spec_info.rs`, built by `InterpModel::new`; position computation in `tlx-sema/src/source.rs`), `"revision"`. `TLCSet("exit", TRUE)` stops the search as in TLC (`ModelChecker.stop` only ends the queue): the current state's successors are all generated and checked, then no new state is expanded; liveness checks only the expanded part (§7.4).
- The contract is in [compat.md](compat.md): three tiers ((verdicts and the state space must agree; incidental implementation choices only need to be valid)), what is outside the contract (command-line and output format), and evidenced differences (D-n). Known limitations and differences: [compat.md](compat.md); supported options, cfg features and module operators: [features.md](features.md).

### 8.2 Testing and validation

[testing.md](testing.md) is the only source for test tiers, commands and expected failures; [benchmarking.md](benchmarking.md) owns performance measurement, and [cloud-verification.md](cloud-verification.md) owns what runs on a cloud instance. The design points: the order of semantic authority is TLC > interpreter > compiled tier; spec tests and the corpus differential tests compare with TLC by compat.md's three tiers; the compiled tier is additionally compared state by state with the interpreter by `TLX_PARANOID` (§6.5.5), and the executors with each other by the testkit's differential tests (`tlx-testkit/src/diff.rs`, `TLX_JIT_VERIFY`).

## 9. Design decisions, risks, open questions

### 9.1 Decisions and their reasons

| Decision | Reason |
|---|---|
| Runtime generic over `Model`; interpreter and compiled tier share search, reporting and liveness | one place for TLC-compatible counting; the interpreter is also the oracle and fallback |
| Shapes from pre-run observation + guards + recompilation (§6.5) | TLA+ is untyped; static inference is imprecise; the interpreter is a reliable observer |
| Generate C and `dlopen` it, with a Cranelift JIT in front (§6.6, §6.7) | compile speed of clang with a narrow ABI; the JIT removes `cc` latency from short runs |
| Speculative native/IR execution with interpreter re-run on any detected problem | the interpreter has the final say on errors and counts; an unsupported operation, a failed guard or any `TLX_ERR`/`TLX_MISS` makes it redo the run and report TLC's exact result. A generated-code bug that passes those run-time checks is not caught by the fallback; it is caught by IR verification at compile time, `TLX_PARANOID` and the sanitizer build (§6.5.5, §6.7) |
| Level-synchronous BFS with adaptive narrow levels (§7.3) | at `-workers 1`, depth and the shortest counterexample equal TLC's; with several workers counts, depth and safety-trace length at an early stop only have to be valid (D-3) |
| States not kept in memory; trace by re-execution (§7.3) | memory per state is the fingerprint plus a log entry |
| Liveness after the search on a recorded behavior graph; TLC's algorithm for VIEW/SYMMETRY (§7.4) | speed in the common case, TLC-identical verdicts where they depend on the concrete state |
| Own semantic layer instead of SANY; SANY/TLC only as test oracles (§3) | no Java at run time; differential tests catch deviations |

### 9.2 Risks

| Risk | Mitigation |
|---|---|
| Speculation fails often, giving many `Dyn`/fallbacks and interpreter speed | `Dyn` and fallback at sub-field / (state, action) / expression granularity; `TLX_COVERAGE` and `scripts/coverage.py` with histograms to improve item by item |
| TLC semantic details differ and counts diverge | differential tests first; the interpreter is aligned with TLC first, then the compiled tier with the interpreter (`TLX_PARANOID`) |
| C compile latency cancels the benefit | background build, JIT first, IR/interpreter until ready; `-O0` first for large sources; content-addressed cache; pre-run time budget; resume after a layout miss |
| Bugs in generated C are silent errors | run-time range/overflow checks return `TLX_ERR` to the interpreter; `TLX_PARANOID` cross-checks; sanitizer build (`TLX_CC_SANITIZE=1`, §6.7) |
| 64-bit fingerprint collisions | the collision probability estimate is reported |
| The own semantic layer deviates from SANY | `sanydiff.py` accept/reject comparison over the whole corpus, message comparison in `tests/sany.rs`; differential state counts expose semantic errors |
| tree-sitter grammar and SANY disagree on a few syntax forms | patch in the CST → AST layer (e.g. `prec.rs`) or report upstream |
| Memory: fingerprint set sized too large/small, states retained for resume | `-fpmem`, `TLX_RETAIN_MB`; the unified memory budget and disk tier ([scale.md](scale.md)) |
| Races and hangs with several workers | level-synchronous BFS; a worker panic stops and propagates at once; `tlx-runtime/tests/explore.rs` |

### 9.3 Open questions

1. Scalability of the `Dyn` interner at very high core counts: it is sharded 64 ways by hash (one lock per shard, the shard number encoded in the handle); a lock-free structure may be needed beyond that.
